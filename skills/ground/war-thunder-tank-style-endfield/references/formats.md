# 材质与 UV 契约

## 分清几种 Alpha

原生游戏 C 图的 Alpha 可以包含涂装混合、磨损等信息；游戏生成的自定义模板又可能把 Alpha 清为零。查看 RGB 时可导出独立查看图，保留原始 RGBA。

固定涂装的 `replace_tex` 和 `set_tex` 使用方式不同。先读实际 BLK 并核对目标材质，再决定颜色 Alpha；不要因为普通图片查看器显示透明就把所有 Alpha 改白。官方说明见 [Custom skins](https://wiki.warthunder.com/cdk/creation_camo)。

N 图是打包材质，不是普通紫色法线图。当前官方说明将 G/A 用于两个切线法线分量、B 用于金属度，R 用于反向粗糙度；旧资源可能涉及历史平滑度转换，须核对版本与实际资源。单纯改变 RGB 亮度会同时破坏多个参数。

转移相关机型的设计时，保留目标结构法线和 AO。作者新增的凹凸可以相对于来源原厂法线分离，再转换到目标切线框架。只有验证方向与结构对应后，才合并回目标 N 图。颜色与材质使用同一遮罩和采样范围。

## 零面积 UV

几何面有面积，UV 却可能退化成线或点。检查的是 UV 三角形的叉积面积，不是几何面积。目标面仍可能双线性读取两到四个纹素。

三角形烘焙之外，为这些采样线和点显式写入颜色及材质，连同必要采样邻域一起检查。扩色只覆盖未被正常表面使用的区域；对真实共用像素先确定表面优先级。

## 预览文件格式

模型输入：

- assembly.obj：已装配的静态网格，含 v、vt、vn、对象名和材质名。
- materials.json：对象根为 materials 数组；每项包含 obj_name、shader 和 texture_slots。第一个槽用于颜色资源匹配。

配置示例：

```json
{
  "textures": {
    "vehicle_turret_c": {
      "color": "../textures/turret.dds",
      "normal": "../textures/turret_n.dds",
      "ao": "../textures/turret_ao.dds"
    }
  },
  "flip_v": true,
  "bump_strength": 0.35,
  "exposure": 1.0
}
```

资源键按模型 texture_slots 的第一个资源名去掉末尾星号匹配。路径相对配置文件解析。不要将示例的方向或材质参数当成其他模型的已验证结论。

默认模型坐标是已验证的 Dagor OBJ 导出约定：Y 向上，车头沿 +X。其他导出来源先确认轴与 V 方向。预览报告会列缺失的原厂材质；这些默认占位不改变实际游戏贴图，不能作为对应材质的验收依据。

## 数据贴图缩放

N 图的 A 是法线分量，固定颜色图也可能含零 Alpha 与有效 RGB。缩放这类数据时分别重采样每个分量，避免把 A 当透明度做预乘运算。包内 `tank_core.resize_data_image` 按分量处理；预览缩小大图也使用它。结构法线需要插值或重归一化时按数据语义核对，不能把普通 RGBA 图片的透明边处理直接套到 N 图。
