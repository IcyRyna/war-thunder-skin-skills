# 终末地风格坦克涂装

按本次车辆、参考和用户评价制作实际贴图。新建工作与正在运行的其他任务隔离；有 WORKSPACE.json 时使用所属项目和任务登记，不改别人的工程或编辑器会话。

## 风格定位

以用户选定的终末地坦克参考为准，先提炼构图、色块走向、标识层级和材质，再落实到目标坦克的实际构件。本轮 A7 原作验证过的起点是深炭黑与灰白分区、荧光黄路径、平行带与圆形节点，以及克制的工业标识；换参考时重新判断，不把一辆 A7 的坐标和布局固化为所有坦克的模板。

设计前阅读 [终末地坦克风格配方](references/endfield-style.md)。本包携带官网标志、A7V 原生 RGB 图集、22 个元素裁片和透明徽记；先看 [素材选择与来源](references/assets.md)，分析标识与布局时再读 [A7V 原作 UV 研究](references/a7v-uv-elements.md)。先确认大块布局和线条，再加入字标与微小技术细节。当前内置工具提供 DDS/BLK 检查与基础模型排错预览，展示图的材质和灯光需要另外对照参考校准。

## 选择适配方式

先看 [跨车型适配与出厂检查](references/surface-adaptation.md)。相近车辆可先试套并按实际表面转移；结构不同的车辆按本车承载面重新构图。把这套风格用于勒克莱尔等其他坦克时，复用标志、路径语汇、信息层级与材料判断，重新建立 UV 和构件对应。A7 的坐标、节点名与色块位置不是跨车模板。混合使用不同车型图集、或需要从零布局时，再读 [混合载具与独立布局](references/independent-layout.md)。

## 确认输入

先查看目标车的实际 BLK、原生颜色图和材质，再定位对应模型。车名相近、文件同前缀或节点同名，都不能证明 UV 或物件功能相同。列清车体、炮塔、炮管、附加装甲、武器站及其他实际使用的图集。

区分游戏生成的涂装模板、原生游戏 DDS、作者成品和作者分层工程。平面成品不等于分层工程。直接复用的位图、按来源测量重建的图形和新画的部分如实登记来源与做法。

用 Python -B 运行脚本。脚本输出写入当前任务，原始输入保留原字节。

## 制作与适配

- 保留目标原 UV、贴图资源与材质分组。共用资源先确认实际采样关系，再决定复用；新增武器站、附加装甲和观瞄组件分别设计。
- 图形按完整承载构件组织，包含正面、立边、孔壁、背面与下沿。只处理朝上的面会留下侧壁白缝。
- 目标范围同时按构件身份和真实表面定位。平面标记必须有承载面约束，避免投到立杆、拉手、光学设备或相邻零件上。
- 相关机型的逐顶点 UV 转移可能跨越来源 UV 接缝，插值后形成碎片。先检查完整 UV 岛及接缝，必要时切开对应范围、逐纹素求对应，或重新构造连续的涂层图形。用户要求按原作复刻时，先保留原作布局与材质，并排检查对应构件，再处理真正不兼容的结构。
- 最近的三维表面不一定承载相同设计。旧车舱盖、孔口、阴影和烘焙结构直接转印到新车，会产生幽灵零件。拆分涂装设计与机械基底，优先保留目标车的结构与 AO。
- 按用户选定的终末地参考确定材料区域；不预设整车只有一种光滑度。N 图按分量处理，UV 旋转或镜像时核对切线法线方向。详见 [材质与 UV 契约](references/formats.md)。
- 整理独立设计源、素材和参数。任务特定坐标、部件白名单和用户评价留在任务，本 Skill 中不固定某一车型的坐标。

原作图形跨多块板、UV 分散或拼接后缺笔画时，先读 [分板 UV 原像素适配](references/native-panel-transfer.md)，在编辑器中确认完整 UV 片与倒角。按原作复刻时保留该处字形和副标题。

## 特别检查细墙和共用 UV

部分孔壁使用零面积 UV：一条线或一个点。普通 UV 三角形栅格化不会写到这些纹素，但模型仍会取色。列出目标面的 UV 面积，针对线、点及其真实双线性采样足迹上色，再向未占用纹素扩色。

共用 UV 只能承载一份颜色。确认可见表面、隐藏面与优先级；不要让隐藏面在 UV 烘焙中把已修好的颜色覆盖回去。材质与颜色的优先级一致核对，不能用平均色或覆盖率证明外观正确。

## 出厂细节与材料

用户要求清洁出厂状态时，分别检查颜色残影、结构法线和材料响应；原生法线包含表面凹凸和磨损，先识别应保留的机械结构，不能用“与原生 G/A 一致”替代清洁漆面检查。旧车的黑孔、螺钉阴影、掉漆与噪点可能随颜色图转移；即使 N/AO 已保留新车，也要清除颜色层里的旧结构。精细度通过原尺寸图、清晰字形和正确接缝验证，不能靠全图模糊或放大分辨率代替。

白漆、黄漆、裸露金属、橡胶与软质附件各按承载材料核对。更换颜色不代表整个部件都应改成相同粗糙度。按 [材料与检查清单](references/surface-adaptation.md) 核对最终 DDS，并保留用户指出区域的同相机近景。

## 核对实际输出

先看全图和原尺寸局部，再用目标模型看侧面、顶部、前后、两个斜视和新增部件近景。比较参考时固定相机、比例、灯光与背景。把图案错位、模型姿态、结构阴影和反光差异分别定位。

输入最终 DDS 再生成预览；生成前的 PNG 通过不代表打包 DDS 通过。对修订范围保留同相机前后对照，并确认保留范围的文件或纹素没有改变。

内置预览是静态 OBJ 的近似材质渲染，不是游戏引擎验证。记录缺失的原厂预览材质、未检查的动画状态和未进行的游戏检查。

## 工具

- `scripts/reproject_surface.py --config CONFIG --part NAME`：通过最近三维表面逐纹素转移到目标原 UV，支持图集写入归属、部件标签、结构法线差值和独立涂层规则。仅适合已确认有对应关系的表面，配置与限制见 [工具契约](references/reprojection-tool.md)。
- `scripts/check_uv_reprojection.py`：检查平铺 UV 写入归属、数据通道缩放，以及对应表面的原作法线与 AO 转移。

- `scripts/export_uv_reference.py DDS... --out DIRECTORY`：从 DDS 导出原尺寸 RGB 查看副本，逐像素核对导出，不改游戏文件或原 Alpha。
- `scripts/composa_mcp.py --out SESSION_DIRECTORY`：连接 Composa 分层编辑器并读取实时工具列表。需要编辑器时按 [可视化与素材提取](references/editor-and-extraction.md) 新建本任务文档，再导入原图与独立标注层。

- `scripts/inspect_skin.py FOLDER --out REPORT.json`：只读检查 BLK 引用、实际文件、尺寸和 RGBA 分量。可加 `--materials materials.json` 核对模型资源名。
- `scripts/tank_preview.py --model MODEL --config CONFIG --out OUTPUT`：离线模型预览。MODEL 包含 assembly.obj 和 materials.json；CONFIG 结构见 [材质与 UV 契约](references/formats.md)。
- `scripts/tank_core.py`：快速查看未压缩 DDS、保留 RGBA 写 DDS，以及读取 OBJ。写出的 DDS 只含顶层；需要 mip 时用验证过的转换器另行生成并复查。

检查器需要 Pillow、NumPy；预览还需要 ModernGL 和 OpenGL 3.3。表面转移工具另需 OpenCV、Numba 和 OpenGL 4.3。使用已有环境，不为普通制作擅自安装服务。
