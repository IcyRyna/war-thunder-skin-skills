# 二次元喷气机的分层编辑

使用当前环境能操作的 Photoshop、Composa 或其他支持所需分层、图文处理与导出的编辑器。先发现实际工具和参数 schema，再组织调用；工具供应商与 Agent 品牌不决定操作能力。不要把界面功能当作已存在的 MCP 工具。Composa 可通过 `scripts/composa_mcp.py` 调用 STDIO MCP，其他编辑器使用各自可用的接口。

Composa 可执行新画布、图像导入、图层变换、文字、形状、选区、调色、保存和渲染等操作，具体以当前 schema 为准。`transform_layer` 的 x/y 表示左上角，`place_image` 的 x/y 表示中心，使用前核对当前接口约定。显式传入需要的文档和图层定位字段。

按设计职责建立底色、大形、人物、主字、辅助字、纹样、结构和配件层。文字使用文字层；复杂图形素材独立保存，栅格化部分保持明确。原图、通道数据和工作预览分别管理。

用户给图与自主检索取得的原立绘都可直接导入，保留原文件和备用层。没有图像模型时，按编辑器实际支持的选区、蒙版、调整层、曲线、透明清除和变换处理边缘、局部配色与明暗；装饰线条用独立形状，文字用文字层。所需姿态无法由现有图适配时，按 [素材与布局](assets-and-layout.md) 查找合适原图；保持用户明确指定的选图要求。

图像模型处理的改色立绘、装饰和草案按 [图像辅助编辑](image-assisted-editing.md) 验收后，以独立图层导入。原版立绘保留为备用层；需要逐像素保留的区域由原图合成。导入前核对生成结果的画布、裁切、位置和真实 alpha，按目标参考对齐，避免投射位置漂移。图像中的字样重新建立为文字层，不能将单张生成图描述为已完成分层工程。

选区与透明清除用于限制绘制范围；抠图后检查头发、白色衣物、饰物和细边。图层变换后观察人物比例与文字清晰度。曲面或 UV 接缝导致的剪切回到对应表面和素材处理，避免反复缩小主图掩盖问题。

先保存工程，再导出绘制结果。正交投射所用透明覆盖图保持参考画布尺寸、位置和方向，隐藏参考底图及诊断层。直接 UV 编辑保持原 atlas 比例，并按需组装 alpha 或材质通道。

导入 SVG、遮罩或裁剪素材后查看实际内容、alpha 和关键位置，不凭图层名、画布范围或“零越界”判断成功。转换器可能忽略 clip／mask；修复时重新导入或替换对应层，再导出并看模型。需要保留矢量编辑性时保存独立 SVG 制作源，栅格导入图层如实说明。交付前按 [工程可继续编辑](packaging-and-validation.md#工程可继续编辑) 做新路径重开与可逆编辑检查。

复合字形的重叠轮廓须核对填充规则。竖干与横杠分别成闭合轮廓时，`evenodd` 可能把交叠处挖空；先在实际栅格输出中检查笔画连接，再决定合并轮廓或使用符合原字形的非零环绕填充，不能仅因每段路径都存在就判完整。曲面上的字形另检查物理比例与真实遮挡。

Composa 的 `save_document` 保存 `.cmps`，`export_image` 可导出常用图片格式。DDS/TGA 与打包通道由文件工具衔接。任意 alpha 写入、分组、蒙版或矢量布尔等功能只有当前接口支持时才能使用。

## MCP 客户端

通过 `--exe` 指定可执行文件，或设置 `COMPOSA_EXE`。没有显式路径时，客户端从 PATH 与常见 Windows 安装目录查找。应用的 AI Control 开关按实际状态处理。

工具列表为空时，先确认应用是否已经运行并完成初始化；按已有会话授权打开编辑器，确认就绪后重新发现工具。接口仍受 AI Control 限制时说明具体开关，并接续已获授权的其他制作路径；客户端不会代为启用该开关。

```powershell
python scripts/composa_mcp.py --out output/editor-tools
python scripts/composa_mcp.py --calls calls.json --out output/editor-session
```

调用文件是包含 `name` 与 `arguments` 的 JSON 数组。客户端先检查整批工具名和必需字段，顺序执行，在首个错误停止；服务器负责完整 schema 校验。每次调用或工具发现都使用新的、空的 `--out` 目录，不能复用旧成功记录；`--timeout` 为每次请求秒数，范围 1–60。指定 `--launch` 时使用 Composa 自身的启动选项；普通发现不启用 AI Control 或修改助手配置。

每轮以 `session.json` 的 `state` 判定进度，只有 `completed` 才表示本批执行完毕。发送前落 `attempts/`，收到的原始响应先存 `responses/`，再生成图片和兼容的单步结果。收到响应后的图片解析或磁盘输出失败，不证明编辑未执行；保留原始响应并核对当前文档，不为重建导出证据重复编辑。

客户端对内嵌图片先完整校验、暂存，再独占发布。目前只物化静态、非隔行的 8-bit 灰度或 RGB PNG，可带 alpha；索引色、16-bit、隔行、动画 PNG 及其他图片类型明确拒绝，原始响应仍留存。此限制是客户端的响应图片处理范围，不改变服务器按实际 schema 导出文件的能力。

超时或没有完整响应时可能已经应用编辑，收据标记 `unknown_applied`；禁止自动重放整批。先在新的只读会话查询实际文档、图层、内容和保存状态，与最后已确认步骤对照，再决定缺少哪一步或是否只需重新导出。服务器返回错误同样先检查已发生的部分操作。未知状态未查明前不把原参数重试当作恢复，旧会话与失败证据保留。
