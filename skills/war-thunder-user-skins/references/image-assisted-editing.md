# 二次元喷气机的图像辅助编辑

将图像模型用于原立绘的受控编辑、主题装饰素材和少量构图草案。优先把已经选中的原版立绘作为编辑输入，按明确任务修改，再导入 Photoshop 或 Composa 工程。人物主体、整机线条、可编辑文字、真实 UV 和材质分区仍按各自职责制作。

## 适合使用的操作

| 需求 | 图像编辑任务 | 后续制作与验收 |
| --- | --- | --- |
| 人物与机身配色不协调 | 局部调整外套、衣料或饰物颜色，保留指定的角色识别色与明暗关系 | 对比原图，再放到飞机实际大色面中看人物是否清晰 |
| 立绘背景影响排版 | 去背景、清理毛边，保留薄发丝、白衣、半透明配件 | 检查实际 alpha，分别在深底与浅底观察边缘 |
| 原素材缺少适合窄长表面的装饰 | 生成独立纹样、花饰、徽记配件或局部延展 | 将可重复的线条重新做成独立形状层，明确尺度和疏密 |
| 立绘光影与设计冲突 | 在需要的区域统一冷暖、阴影或高光强弱 | 保护面部可读性，避免覆盖原画线稿与固有色 |
| 需要比较整机视觉方向 | 依据真实飞机轮廓、选定立绘和色板，生成少量布局草案 | 按实际表面和 UV 重建，使用真实模型检查七视图 |

单纯可逆的平涂改色，编辑器的选区和调整层可能更准确；涉及复杂纹理、边缘、局部光影重绘时使用图像模型。按任务选择，避免将简单修改扩大成整幅重画。

## 模型与执行路线

指定 GPT Image 2.5 时，精细原立绘编辑优先请求 `gpt-image-2.5-sunburst`。`gpt-image-2.5-flare` 可用于有明确速度要求的候选比较，使用同一组输入和检查标准后决定是否适合。用户指定完整模型名时按其要求执行。

先检查实际工具 schema。一般图像编辑优先使用内置图像工具；有本地路径的输入先查看，再通过 `referenced_image_paths` 传入。只有缺少本地路径的对话图片才按工具规则使用最近图片参数，不能同时使用两种机制。去背景或透明素材明确要求透明输出，其他编辑保留输入的透明状态。

精确版本要求必须落实到有模型选择能力的工具、API 或官方配套 CLI。工具没有 `model` 参数时，在提示词中写模型名不能完成切换，也不能宣称已调用 2.5。此时记录版本未确认；需要精确 2.5 的任务使用已经核实的模型选择路线，不静默换成其他版本。

按当前官方模型页和图像编辑接口核对模型名、参数与可用权限。原立绘编辑使用 `/v1/images/edits` 并传入真实输入图片。透明输出使用 PNG 或 WebP。不要因为其他模型有同名参数，就给 2.5 添加未经确认的 `input_fidelity`。

使用运行环境自带的 imagegen CLI 时先查看 `--help` 和参数验证逻辑，不复制或修改系统 CLI。明确传入 `--model gpt-image-2.5-sunburst`；旧版助手脚本可能只接受 `auto`、`1024x1024`、`1536x1024`、`1024x1536` 和 `low/medium/high/auto`，按当前助手脚本支持的值调用。API 新增的尺寸或质量值不能直接当作本地助手脚本已经支持。先做 `--dry-run` 核对请求，再按已授权的编辑任务实际执行。

下面是准备好原图与编辑指令文件之后的 Windows 调用示例；路径均相对于当前制作工程：

```powershell
$codexSkillRoot = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$imagegenCli = Join-Path $codexSkillRoot 'skills/.system/imagegen/scripts/image_gen.py'
python "$imagegenCli" edit --image 'assets/character-original.png' --prompt-file 'edits/character-recolor.txt' --model gpt-image-2.5-sunburst --size 1024x1536 --quality high --background transparent --output-format png --out 'assets/character-recolor-v1.png' --no-augment --dry-run
```

实际编辑使用同一组已核对参数去掉 `--dry-run`，并使用该环境已经配置的凭据。请求预检查只证明本地构造了指定模型的请求；API 返回成功、输出图片存在并完成观察之后，才能报告实际编辑已执行。提示词、模型请求名和检查结果留在制作工程，凭据不进入工程或分发包。

## 原图、修改范围与提示词

1. 查看原图，明确其角色版本、原画风格、分辨率、透明状态和适合的承载面。保存原文件，每次编辑生成新的版本文件。
2. 将输入职责写清：第一张是需要编辑的立绘；其他图片只提供色板、纹样或目标效果。指定来源的角色身份、姿态和造型，避免把色板参考中的人物替换进来。
3. 列出允许修改的区域、目标色和保持项。脸、五官、表情、发型轮廓、身体比例、姿态、手指、服装剪裁、装备与线稿默认保持；确需修改的项写入本次目标。
4. 每次修改一个主要变量，例如先改外套配色，再处理透明边缘。为原图和少量候选提供相同的观察尺度，用具体可见问题决定下一次修订。
5. 保留生成素材的出处关系和版本。衍生图的说明不能把它冒充为原版立绘。

局部服装改色的提示词示例：

> 编辑输入的原版角色立绘。仅将外套原来的红色衣料调整为深蓝色 #244C72，将原外套窄边饰调整为浅青色 #93D5D9，保留原衣料明暗、褶皱和纹理。脸、肤色、眼睛、表情、头发、手、姿态、身体比例、服装结构、徽记与装备保持原样。保留原画的线稿和绘画风格，不新增文字、光晕、花饰或物件。人物完整呈现，位置和留白尽量保持原样，输出透明背景。

实际提示词中的区域和颜色必须依据已查看的原图及本次配色方案确定。抠图、延展、光影重绘分别写专用指令，不把无关改动合并进一次请求。

API 支持编辑遮罩时先核对格式、尺寸与 alpha 语义；图像编辑接口的透明遮罩区域表示可编辑区域。提示词与遮罩仍不能保证保护区域逐像素不变。确需精确保留的脸、头发、徽记等部位，由 Photoshop 或支持相应功能的编辑器从原图合成，只采用生成图中通过检查的修改区域。

## 导入与验收

把原图和候选并排看，检查角色识别、五官、手指、姿态、衣物结构、线稿、标志、颜色角色和多余元素。去背景素材检查真实 alpha 和深浅背景下的边缘，透明棋盘格画进 RGB 不能算透明输出。任何失败项返回对应局部修订，不以提示词写了“保持”作为通过证据。

生成结果的画布尺寸、裁切和位置可能与原图不同。先在编辑器中核对并恢复所需的尺寸、比例、位置与留白，再参与正交投射；不把尺寸文字要求当作真实结果。避免拉伸人物来填满 UV，保持原有角色比例。

通过检查的结果作为独立图层导入，原图保留为备用层。生成图片是栅格素材，不能报告为已经拥有可编辑的衣服、头发、文字和矢量层。文字按实际文案重建为文字层；线条和重复装饰按 [线条与配色](linework-and-color.md) 建立可修改的结构层。导入步骤见 [编辑工作流](editor-workflow.md)。

在实际飞机的顶底、两侧、前后和斜视中检查人物尺度、配色、线条连续性与表面接缝。生成的飞机草案或七视图仅作视觉方案，真实几何与投射检查仍使用目标模型。

图像模型可绘制银、金或亮漆的视觉草案。游戏中的金属、粗糙度、法线和颜色 alpha 按 [UV 与材质](materials-and-uv.md) 从真实通道定义制作；RGB 中画出的反光不代替这些数据。不能将生成图片直接作为打包的 `_n` 材质贴图。

记录输入原图、实际请求模型、执行路线、参数、提示词、输出版本与具体观察结果。请求检查、实际编辑成功、素材检查、模型预览和用户美术验收分别记录；加入图像编辑流程本身不证明整机审美已经通过。
