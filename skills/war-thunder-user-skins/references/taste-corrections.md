# 审美纠偏：字体、配色、布局、漆面

模型凭感觉做的选择有固定偏向：用最常见的字体，往每个面都放点东西，配霓虹色，把一切做得中等、居中、对称，觉得空就加细节，自评时说"高级""和谐"。用户说"AI 审美差"，指的就是这些。本文件把偏向逐条列出，每条给出改法和检查办法。

用法：

1. 开工前读一遍，写设计稿时按"改成"一栏做。
2. 设计稿写好后跑 `python -B scripts/design_lint.py --design design/design.json`。error 必须修；warn 逐条修，或在设计记录里写明为什么保留。
3. 出图后过文末的[交付前闸门](#交付前闸门)。

风格 skill 的数值优先于本文件的默认值，但这里列的偏向在任何风格里都是错的。`design_lint.py` 只查得出写进设计稿的问题，编辑器里手工加的字和图同样按本文件自查。

## 先改掉的思维习惯

| 偏向 | 改成 |
| --- | --- |
| 求稳取中：中等大小、中等饱和、居中、对称、每个面各放一样东西 | 先定主次。全机只有 1–2 个焦点（通常是主翼人物和机背主图形），其余面让位；大、中、小差距拉开到 3 倍以上 |
| 觉得空就加：加小件、加细线、加字 | 先查大形：放大母形、加深通道、把人物放大。用户说"空"时先改大中形（见 [美术设计](art-direction.md)） |
| 在展开图上排版、判断构图 | UV 不是视觉。构图只在模型渲染上判断，展开图用来找原因 |
| 一轮改很多处 | 每轮只改差距最大的 1–2 项，改完前后并排对比 |
| 自评用形容词：高级感、和谐、完美融合、视觉冲击力 | 不写形容词，只写可核对的事实：面积百分比、字号、色值、哪一处和参考不同。自评分不算证据 |
| 只出一个"稳妥"的方案 | 构图阶段出 2–3 个差别明显的三值缩略图（见 [审美基线](aesthetics.md#审美流程)），交给用户或参考来选 |
| 用户否定后换个说法再交同样的东西 | 把用户原话和被否定的做法写进对应 skill 的反例表（如风格 skill 的"不要这样做"），下次开工先读 |

## 字体

字是模型最容易出错的一项。

### 选字体

| 默认倾向 | 为什么难看 | 改成 |
| --- | --- | --- |
| 不写字体，用库或编辑器默认（Arial、DejaVu、Segoe UI） | 办公文档味 | 显式写字体。拉丁字母用几何或方形无衬线：Windows 自带 Bahnschrift（`C:/Windows/Fonts/bahnschrift.ttf`，可变字体，`variation` 取 `Bold`、`SemiBold`、`Light`）。中文用微软雅黑粗体 `msyhbd.ttc`、等线粗体 `Dengb.ttf` 或黑体 `simhei.ttf`；日文用 `YuGothB.ttc` 或 `meiryob.ttc` |
| Impact、Arial Black、科幻装饰字、手写体、书法体、斜体 | 表情包、页游广告 | 同上。要力量感就用 Bold 加宽字距，不用压扁的海报字 |
| 宋体、细明体 | 细笔画在游戏距离消失 | 黑体类 |
| 每组字换一种字体 | 散 | 全机一个字族、两档字重（Bold 做主名，Light 或 Regular 做副行）；有中日文时另加一款黑体 |
| 中日文沿用拉丁字体 | 显示成方块 | 显式指定中日文字体并渲染确认；`design_lint.py` 报 `missing-glyphs` / `cjk-without-font` |

### 写什么字

| 默认倾向 | 改成 |
| --- | --- |
| 编英文口号和假技术字："CYBER""NEON""TACTICAL UNIT 07""SYSTEM ONLINE"、随手编号 | 每一行字都说得出出处：角色名、作品名、阵营或组织名、机型与制造商、真实的技术标注（JET INTAKE、NO STEP、DANGER、RESCUE）。说不出出处就删 |
| 假日文、凭印象写汉字、机翻 | 用角色的官方名称；不确定写法就用官方拉丁拼写 |
| 每个面都放字 | 主名每侧一次；全机字组不超过 5–6 组；技术字聚成 1–2 簇 |

### 字号、字距、方向

| 默认倾向 | 改成 |
| --- | --- |
| 同一面上字号几乎一样（如 0.24 m 和 0.30 m） | 拉开层级：主名 : 副行 : 注释 ≈ 1 : 1/3 : 1/8，相邻两档至少差 2 倍；不想分层就用同一个字号 |
| 全大写不加字距 | 主名 `tracking` 0.05–0.12，小副行 0.2–0.3；中文 0–0.05 |
| 字悬在空白正中，或随手斜放 | 字的基线贴着一条已有的边（母形边、深色道边、面板线、前缘），沿机轴或前缘后掠方向排 |
| 主名、副行、细线各自散放 | 做成锁组：主名＋细线＋副行是一块，块内间距为字高的 0.3–0.5，同组左对齐 |
| 描边字、投影、外发光、渐变字、浮雕 | 实色字。要和底分开，就把字放进深色带；最多配一道签名色细线 |
| 小字用细体（字高 8 cm 以下用 Light） | 小字用 Regular 或 Bold；Light 只给大副行 |
| 左右两侧的字按同一方向写 | 两侧都要从各自外侧读正：设计稿里左侧通常要 `flip`。先用带方向标记的试写（如 `R→`）渲染确认 |
| 字压在弯折、格栅、舱门或左右共用 UV 的部位 | 只放 `surface_map.py` 的灰色平整区；共用 UV 处另一侧显示同一块像素，字会反 |
| 拉丁字母逐字竖排堆叠 | 拉丁字只整行旋转 90°；逐字竖排只用于中日文 |

## 配色

| 默认倾向 | 为什么难看 | 改成 |
| --- | --- | --- |
| 霓虹赛博：青＋品红＋紫 | 千篇一律的 AI 图 | 签名色从角色原图取样（`sample_color` 半径 4–8 px，取发色、瞳色、标志服饰），不按角色名或印象选色 |
| 纯黑 #000000、纯白 #ffffff、屏幕原色（#ff0000、#00ffff、#ff00ff） | 刺眼、发平、像没印上去 | 近中性炭 #2b2b2c–#424347，近白 #e7e7e7–#f4f4f4；签名色用取样值。文字不写 `color` 时默认是 #ffffff |
| 多个饱和色等量并列（红蓝、红金、青粉条纹） | 互相抵消、发闷 | 只用一个饱和色族；第二个饱和色只做 ≤2% 的点缀 |
| 各色面积差不多 | 没有主次 | 按 [审美基线](aesthetics.md#配色一个签名色) 的面积表：深底 50–65%、签名色 20–35%、强调色 3–8%、点缀 ≤2%；用 `atlas_palette.py` 量 |
| 色相渐变（蓝→紫→粉的"晚霞"） | 素材网站味 | 同一色相做 10–20% 的明度渐变，沿气流方向，全机方向一致 |
| 发光、光晕、霓虹边、金属渐变、镜头光斑 | 游戏有真实光照，画上去的假光在机身上显脏 | 不做。质感来自马赛克、半调和亮漆反光 |
| 白色画成细长线：贯穿机身的细针、平行赛车条、前缘白细边、单独的白色长伴线 | 用户：“很喜欢弄些莫名其妙的白线”；远看像划痕 | 白色只做两类：有体量的形（楔形、刀片、琴键），或主图形里成组的渐尖尖片（两头或一头收成真尖点，最宽处约为长度的 7–12%，与机轴夹 6–13°，起止错开）。它们集中在主图形周围、共用方向；贯穿机身的长细线用签名色，贴着色块边走。主白色图形的同角度细描边回声可以保留（id 写 echo）；`design_lint.py` 报 `thin-white-line` |
| 每个面都用最饱和的颜色 | 刺眼、抢人物 | 最饱和的颜色只给小面积和线；大面暗一档，或做成马赛克 |
| "高级灰"：一切降饱和，中灰一片 | 糊、没有结构 | 先保证深、中、亮三档：`style_board.py` 的灰度行能分出三档 |
| 用黑色描边勾人物和图形 | 贴纸 | 不描边。人物靠深场衬托，图形之间靠负形缝分开 |
| 浅色人物放在浅色底上 | 人物消失 | 人物所在的面改成深场 |

## 布局

| 默认倾向 | 为什么难看 | 改成 |
| --- | --- | --- |
| 盖章：每个面正中放一个元素 | 贴纸感，各面互不相干 | 元素从边出发、跨部件延续：母形从机头经翼根延续到尾部，人物铺满翼面、出画到边 |
| 均匀撒满：每个面密度相同 | 碎、没有焦点 | 安静底 55–70%；密度集中在 1–2 个焦点，其余面让位 |
| 所有元素差不多大 | 没有层次 | 大、中、小三档，面积比约 1 : 1/3 : 1/10；大形全机只有 1–3 个 |
| 方框、卡片、圆角矩形、徽章框 | 像 UI 截图、像贴纸 | 不用框。强调靠实心楔形、负形缝或色场边界 |
| 方向随意，或与气流垂直 | 乱 | 角度只用机轴、前缘后掠和后缘方向（至多再加一个斜向）；`design_lint.py` 报 `too-many-angles` |
| 差一点对齐、差一点平行、边缘刚好相切 | 像失误 | 要么严格对齐或平行，要么拉开至少半个元素宽 |
| 同一元素复制粘贴排成一排 | 机械 | 序列要等距、逐个递减、有起有止，或者从同一个母形切出来 |
| 人物缩在角落的小矩形里 | 贴纸 | 覆盖翼面 60% 以上，干净抠图 |
| 每个面"各自平衡"，左右随意不对称 | 散 | 机身线组左右镜像；人物可以不对称 |
| 等粗圆头彩线平行排列 | 马克笔、意大利面 | 线条是填充形：渐尖、斜切，或接入另一条带 |
| 几条宽窄不同的线叠在一起做"发光" | 廉价 | 一条路径只画一次；要和底分开，靠旁边的深色道 |

## 漆面

| 默认倾向 | 为什么难看 | 改成 |
| --- | --- | --- |
| 为了“有飞机感”保留原机法线、把原机凹槽或模糊结构层压进颜色、留原机 R 的起伏当旧化 | 用户：“自带原皮的纹路，黑不溜秋”；任何光照下都是一层深色纹路 | 整机一层涂层：`coat_material.py`，R 173（白底 228）、B 0、法线压平；纹路只在反光里出现，见 [整机一层涂层](materials-and-uv.md#完整重涂默认整机一层涂层) |
| 从原厂贴图描面板线画进颜色，线断、斜线成台阶、脏迹被描成线 | 用户在游戏里看莱万汀 v3：“线条这么脏”“线条粗糙” | 默认不画（参考作者 F-2A 没有）；要画就过 `panel_lines.py` 的质量闸门，并在原尺寸检查里和参考并排看不出差别，见 [面板发丝线](materials-and-uv.md#面板发丝线) |
| 只看缩小的预览图就交付 | 8192 图缩到 1600 px，2 px 的线和边缘好坏看不出来 | 交付前做 [原尺寸检查](packaging-and-validation.md#原尺寸检查) |
| 立绘保留原图浅色背景，再大片渐隐 | 深底上一片灰雾，显脏 | 人物干净抠图，背后直接是深底 |
| 光滑度取中间值（100–130）求稳，人物区再调低 | 漆面发灰发闷，高光碎 | 用参考作者实测值，人物和字与涂层同值 |
| 颜色图 4096² | 细线和小字发虚 | 主体颜色图 8192² |

## 交付前闸门

逐条写"通过／不通过＋证据"，不写形容词：

1. `design_lint.py`：0 个 error；每个 warn 已修好，或写明了保留理由。
2. 字体：用了几个字族、几档字重；`design_lint.py` 输出的文字清单逐行写出处。
3. `atlas_palette.py`：饱和色族有几个，签名色和强调色面积是否落在基线或风格 skill 的区间内。
4. `style_board.py` 灰度行能分出深、中、亮三档；眯眼行能读出机头到机尾的主方向。
5. 焦点：说出全机 1–2 个焦点在哪里，安静底占多少。
6. 在模型渲染上（不是展开图）看过字的方向、人物尺度和各区域近景。
7. 和参考并排，先写出 3 处我们比参考差的地方，再决定交付还是再改一轮。
8. 漆面：材质收据写出 R、B、G/A 平值和保留的结构比例；颜色图里没有从法线提取的模糊结构层；主体颜色图尺寸；面板发丝线：不画，或写出质量闸门的数值和原尺寸检查结果。
9. `surface_map.py` 的 `seam_items`：没有图形被凸条侧壁之类的接缝切断，或逐条写明为什么可以。
10. 原尺寸检查：`detail_sheet.py` 截过每个部位（机背焦点、翼面、尾面、侧面细线、立绘边缘），在 Composa 或检查图里按 1:1 和参考并排看过，边缘干脆、粗细一致、没有锯齿、断线和灰雾。
