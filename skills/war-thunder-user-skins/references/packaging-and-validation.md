# 二次元喷气机涂装的输出与检查

工作区保存可编辑工程、素材来源、原始通道和修改记录。游戏包只放目标喷气式飞机 BLK 与它实际引用的 DDS/TGA。高低清及不同飞机改型的适配版本分别检查文件名、资源映射、尺寸和 UV。

写入前枚举整组目标，包括自动派生的预览、遮罩、深度、JSON、ZIP 和来源记录，拒绝与任何输入或已有资产冲突。转换和构建使用同盘暂存，校验完整后提交；失败只清理本次新建的未提交内容并留失败收据，不删除原素材或把部分产物称为成功包。恢复前核对实际文件和收据状态，不能用覆盖原文件或复用旧成功记录掩盖失败。

## 构建辅助

`scripts/build_skin.py` 从单架喷气式飞机模板、编辑器导出图和确认过的原贴图组装 TGA/BLK 包。输出目录必须在模板目录外，并使用新的空目录。模板有重复资源映射时先解决歧义。

`--paint` 使用“精确 from 资源名=编辑器图片”；`--reference` 指定对应真实原贴图。没有编辑的颜色与材质保留原数据，颜色编辑默认保留原 alpha。`--channel` 使用“精确 from 资源名:RGBA 字母=8-bit 灰度图片”，只替换明确指定通道。输入比例必须与原 UV 一致。

```powershell
python scripts/build_skin.py --help
python scripts/inspect_skins.py scan output/skin-package --out output/skin-check --strict
```

构建器输出 32-bit TGA、BLK、ZIP 和组装记录，检查 TGA 像素往返及配置。输入 BLK 结构有重复或歧义时先解决，不能让重写后的 BLK 隐藏输入错误。构建器不直接输出 DDS，不模拟游戏材质着色器；DDS 另建独立版本。

## DDS 与实际 mip

`scripts/dds_variant.py` 接受已经检查的 TGA／BLK 目录，以 `--texconv` 指定受支持的官方 DirectXTex 转换器。当前工具核对固定的 May 2026 二进制及哈希，缺失或版本不符时明确失败；二进制不内置于 Skill。选择全新输出目录，不覆盖 TGA 主包。

```powershell
python scripts/dds_variant.py --input output/tga-skin --out output/dds-rgba8 --texconv tools/texconv.exe --format rgba8
```

默认 `rgba8` 保留顶层通道像素；`--format bc3` 生成单独的有损压缩实验。确认过的颜色资源按 `color`、打包材质按 `data` 处理，未知用途拒绝自动猜测；必要时用 `--role "精确from资源名=color"` 或 `=data` 明确指定。转换生成新的 BLK、DDS 包、ZIP、`.dds.json` 收据及 `.mips.zip` 实际解码图。

工具先逐通道以浮点 BOX 生成完整 mip 链，再让 texconv 保留现有各级转换编码；不依赖转换器标志自动保证过滤语义。颜色 RGB 以 sRGB 解码、线性过滤后再编码，alpha 独立按数值过滤，不预乘；材质 RGBA 按独立线性数据处理。逐层读取实际 DDS 直至 1×1，RGBA8 各级与预生成链逐像素核对，有损版本记录各级通道误差，并核对配置引用。打包 G/A 的 mip 是数值基线，不宣称法线向量感知过滤或游戏 shader 正确。有损版本与无损基线比较脸、字、线、透明边和接缝；未验证的压缩方案不替代主包。mip 生成与离线取样不能证明游戏运行时 mip／LOD 选择。

## 静态检查

`scripts/inspect_skins.py` 只读源目录，输出放在源目录外。格式与 BLK 检查只需 Python 3.10+；图片预览需 Pillow。`--hash` 会读文件全部字节，按比较需要使用；`--strict` 在发现静态错误，或显式请求的预览解码失败时返回非零状态。未请求像素解码的扫描只能说明它实际检查的头部与配置，不据此称所有纹理或 mip 已解码通过。

```powershell
python scripts/inspect_skins.py preview textures/body.tga --out output/texture-check
```

工具不查询游戏资源库、不执行 include、不验证 UV 或自动修复。DDS 数组、体和立方体不生成普通预览；二维顶层预览限制为 8192×8192。缺失目标、重复映射和通道异常结合目标资源判定影响范围。

## 模型与实际效果

项目已有七视图标准或用户要求沿用前稿时，保存并复用其相机方向、机腹朝向、画布、图格、背景和展示比例；不随修订更换展示模板。材质特写或新的展示角度另行输出，不替换标准七视图。检查两侧、顶底、接缝、镜像、文字方向、人物识别和曲面拉伸；修改外挂时再检查相关配件。先看缩小整体，再看原生局部。近似漫反射预览只说明布局，光泽与材质需对应渲染条件核对。

当前材质的完整环境图、投诉部位近景及配对输入收据随当前作品保留，整理时不能只留平光七视图和失去图像对象的旧通过记录。整机受光正常也不能替代人物尾面等局部检查；发现旧凹凸残留时，对实际投诉区域做同相机法线隔离并返回材质修正。

清晰度修订分别关闭源稿到 atlas 的细节保真与最终模型上的可读性。沿同一位置追查“原素材 → 实际源层 → 编辑器导出 → atlas → 包内实际解码 → 安装文件”，定位首次出现的细节损失；运行时过滤、mip／LOD 与目标 shader 另记实际已查或未知范围，不能用下游放大掩盖上游缺陷。用户提供问题截图时，围绕实际受影响的整段路径，复用可取得的视向与机体屏幕占比，检查机背曲面、翼根、窄间距和可见掠射段的线宽、对比、连续性与收束。平翼局部放大更清、局部误差下降或 8K 尺寸不证明这些路径合格；按线条职责检查主辅轮廓及空隙是否成立，有意弱化的细线另作说明。改变机体在画面中的占比、只展示更有利视角或从背向面投影线宽，不能当作对应问题视角的通过证据。

在检查开始时列出当前 brief 的必需要求，按“表面／要求 → 实物视角 → `pass`／`fail`／`uninspected` → 复查”记录。技术合规与基本识别／构图分栏：头型、发型头饰及肩臂动态完整，指定人物面齐全，明确线条层级与密度成立；“有像素、不误涂、脸可认”不能替这些条件通过。单尾查左右，双尾查各片内外；能补看的必需面必须补看，失败先修。确无能力可交付受限候选，总体不得全通过；禁止或不支持的游戏检查另记范围。

逐面检查装饰线条的路径、密度、收束和颜色职责，尤其关注机背各段的主辅线条、垂尾人物以及无人物机腹的主题组织。脸、颈肩、关键手势或主名字被结构切开时，返回布局修订后再交付候选；检查翼下和平尾是否残留主图碎片。正交预览与斜视都应看，没看见的尾面或被遮挡部位按未检查记录。

无人物机腹以最终贴图映射到模型后的效果为准，不能仅凭底视源稿没有人物通过。需要时结合 [人物 UV 遮罩诊断](orthographic-workflow.md) 检查共享纹素和残片；外挂遮挡、模型空隙与未显示表面分别处理，缺少腹部视角时保留未检查状态。

要求金属或亮漆时分别检查 R/B 修改区域、按本次明确合同保持或局部修改的 G/A、遮罩外数据与高光下的人物可读性。证实旧涂层凹凸违背新漆目标时，按独立遮罩移除或重建，并核对必要机械结构及域外保持；不能将 G/A 全量原样保留作为通用门禁。线条和人物完整性检查通过不代替表面质感验证。

材质对照保留相同输入与保持不变的区域，说明实际改变了哪些通道和哪些 UV 部位。近似渲染的对照只支持该环境下的差异，不据此声称目标游戏效果已验证；实验用的通道图、蒙版和参数记录留在工作区，游戏包只装最终选定的数据。

按项目约定选择游戏或离线检查。未进行游戏检查时，明确“静态检查通过，尚未实机验证”。发布、市场收录和发送第三方按用户请求执行，交付规则从当时的官方规范核对。

交付说明包含文件位置、安装方式、具体变更、已完成的检查与实际限制。素材 credit 保留准确；内部项目资料与当前成果分开。

用户报告安装后与预览不同或仍有旧问题时，先只读核对实际安装目录的 BLK 映射、被引用贴图的文件名、尺寸、编码及逐文件哈希，与当前交付和正式预览所用输入对应；确认用户所选目录是否为当前版本。文件身份不一致时先解决版本或安装问题，不能直接归因游戏过滤、设置或着色器。读取安装文件不要求启动游戏，已禁止的游戏检查仍保持未验证。

## 工程可继续编辑

从已保存原生工程复制到新路径并重新打开，保留交付原件字节。核对关键图层、文字内容与实际像素；进行一次文字编辑或位置变换后撤销，重新导出，与预期画面比较。无文字或没有对应能力时记录实际替代的可逆编辑及限制，不声称验证了不存在的能力。只有保存成功或 ZIP 校验成功不足以证明工程可编辑。

分别说明原生文字／形状、独立 SVG 源和栅格图层的可编辑范围。SVG、蒙版和裁剪经过转换后检查实际 alpha、关键形状与位置；非空不等于形状正确，零交集也可能是内容丢失。最终修订须出现在真正的编辑器导出及模型中，不能只更新脚本参数或诊断图。采纳工程输出为正式色图前，明确实际源层的 straight／premultiplied 与量化存储合同，记录实际导出相对原基准的差异，并以严格重开及撤销后再导出一致确认；后续模型与交付绑定该实际工程导出及已声明的通道组装结果。关键画面允许差异时记录具体原因；未解释的丢层、遮罩丢失或导出不一致先修复。

## 验收状态

分别记录技术合规、基本识别／构图及用户美术评价。用户否定的版本标记失败反例，保留对应实物、版本哈希、反馈和漏检原因；旧技术通过仍仅描述当时技术范围，不可据此沿用美术通过或继续列成功样例。独立审查与实物冲突时回到具体裁切、覆盖和线条不足复查，不投票表决。有限认可保留限定；新修订重新验收，不能继承失败版或其他作品的认可。

每项通过绑定本版输入、实际检查对象以及适用的视角、显示尺度和受光条件。工具回归、字节／配置、局部重建、模型线条可读性、近似材质和目标游戏结果分别命名；本次局部通过旁边继续显示未解决的既有 fail 或未检查项。原材质只完成数据保持时按实际写明“数据保持通过；既有外观失败未修”，不用带模糊限定的总体 pass 吞掉该失败。

按用户要求保留或清理失败版本。需要归档时，将失败工程、贴图、预览和必要历史版本集中保存，逐项核验完整性后清理散落副本；明确要求删除旧版或失败归档时，先抽出当前作品仍需的几何、模板与素材并更新现用依赖，再按授权范围删除，不另行囤积失败包。作品实际名称与具体评价留在项目记录中。验证结束后清理可从交付输入重建的解包副本、临时导出和重复游戏包，工作区保留单份必要基底；无损压缩保存参考通道时校验像素，避免同一未压缩贴图在多个验证目录中重复常驻。
