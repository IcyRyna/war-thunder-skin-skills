# 二次元喷气机涂装的输出与检查

工作区保存可编辑工程、素材来源、原始通道和修改记录。游戏包只放目标喷气式飞机 BLK 与它实际引用的 DDS/TGA。高低清及不同飞机改型的适配版本分别检查文件名、资源映射、尺寸和 UV。

## 构建辅助

`scripts/build_skin.py` 从单架喷气式飞机模板、编辑器导出图和确认过的原贴图组装 TGA/BLK 包。输出目录必须在模板目录外，并使用新的空目录。模板有重复资源映射时先解决歧义。

`--paint` 使用“精确 from 资源名=编辑器图片”；`--reference` 指定对应真实原贴图。没有编辑的颜色与材质保留原数据，颜色编辑默认保留原 alpha。`--channel` 使用“精确 from 资源名:RGBA 字母=8-bit 灰度图片”，只替换明确指定通道。输入比例必须与原 UV 一致。

```powershell
python scripts/build_skin.py --help
python scripts/inspect_skins.py scan output/skin-package --out output/skin-check --strict
```

构建器输出 32-bit TGA、BLK、ZIP 和组装记录，检查 TGA 像素往返及配置。它不直接输出 DDS，不模拟游戏 mip 或材质着色器。需要 DDS 时使用实际转换器并重新读取验证编码、通道、mip 和文件映射。

## 静态检查

`scripts/inspect_skins.py` 只读源目录，输出放在源目录外。格式与 BLK 检查只需 Python 3.10+；图片预览需 Pillow。`--hash` 会读文件全部字节，按比较需要使用；`--strict` 在发现静态错误时返回非零状态。

```powershell
python scripts/inspect_skins.py preview textures/body.tga --out output/texture-check
```

工具不查询游戏资源库、不执行 include、不验证 UV 或自动修复。DDS 数组、体和立方体不生成普通预览；二维顶层预览限制为 8192×8192。缺失目标、重复映射和通道异常结合目标资源判定影响范围。

## 模型与实际效果

检查两侧、顶底、接缝、镜像、文字方向、人物识别和曲面拉伸；修改外挂时再检查相关配件。先看缩小整体，再看原生局部。近似漫反射预览只说明布局，光泽与材质需对应渲染条件核对。

逐面检查装饰线条的路径、密度、收束和颜色职责，尤其关注较长机身、翼根、尾面与机腹是否缺少主题组织。要求金属或亮漆时分别检查 R/B 修改区域、G/A 保存、遮罩外数据与高光下的人物可读性；线条检查通过不代替表面质感验证。

按项目约定选择游戏或离线检查。未进行游戏检查时，明确“静态检查通过，尚未实机验证”。发布、市场收录和发送第三方按用户请求执行，交付规则从当时的官方规范核对。

交付说明包含文件位置、安装方式、具体变更、已完成的检查与实际限制。素材 credit 保留准确；内部项目资料与当前成果分开。

## 验收状态

分别记录技术检查与美术评价。待评审作品保持待评审；明确失败的作品标记失败；勉强成功的作品保留限定；用户认可的优秀作品才可作为相应质量的示例。更新当前作品索引时不得沿用被用户推翻的自评结论。

用户要求只保留成功作品时，将失败工程、贴图、预览和必要的历史版本集中归档。归档前检查当前作品的文件依赖，将仍需使用的几何、模板或素材保存在合适位置；完成归档文件的逐项完整性校验后，再按明确范围清理散落副本。作品实际名称与具体评价留在项目记录中。
