# 战雷二次元喷气式飞机痛涂

按目标喷气式飞机与二次元角色或作品主题，制作实际可编辑、可继续修改的痛涂。由助手完成素材选择、构图判断、编辑操作、模型检查和打包交付。制作任务持续到一版实际成果，普通设计决定自行选择合理值。

## 执行范围与项目约定

适用对象是固定翼喷气式飞机，视觉主题是二次元角色、动漫或游戏作品。历史复原、无二次元主题的通用涂装，以及地面载具、直升机、舰船和螺旋桨飞机涂装，不属于本技能的执行范围。

制作或修订任务执行完整链路；点评、选型和方案任务聚焦指定素材与设计问题；格式检查或适配任务按改动范围处理。明确“不重做”时保持已有作品，修订时保留已经接受的部分。

项目存在 `.skin-workshop.json` 时先读取其中的目标飞机、工具、验证方式、覆盖要求和素材获取约定。当前对话与项目约定优先于默认值。只有缺少信息会改变整体作品时，问一个聚焦问题。

内部项目资料、配置、过程记录和非交付文件留在工作区。对外说明聚焦当前作品的设计、用法和验证结果。素材出处与所用素材的 credit 按实际要求保留。

## 美术验收与作品留存

技术检查通过只说明格式、配置或制作步骤满足对应条件。成功作品必须有用户的实际美术认可；自评分、工程数量和打包结果不能代替验收。用户评价“一般般”或“勉强成功”时保留这个限定，不提升为优秀范本或成熟能力证明。

按项目约定维护当前作品索引，只展示已获认可的作品并注明认可程度。明确失败的作品退出当前作品区，按用户要求集中归档；保留其实际评价，避免在后续任务中继续当作成功示例。归档时先保护仍被当前作品使用的共享资源，再校验归档完整性。

## 制作流程

1. **确定素材与承载面。** 核对喷气式飞机改型、二次元主题和角色版本；查看候选素材，判断脸、肩线、动作、头发和装备是否适合目标表面。取得可编辑的实际素材，并记录来源。原立绘需要局部改色、去背景、修边或补充装饰时，使用图像编辑模型生成独立衍生素材，保护角色身份与原画结构，再与原图比较。指定 GPT Image 2.5 时优先选择 Sunburst，并核实实际请求的模型。方法见 [素材与布局](references/assets-and-layout.md) 和 [图像辅助编辑](references/image-assisted-editing.md)。
2. **组织整机关系。** 先安排人物、主名字和大色面，再建立连接机首、机身、翼根与尾面的主线条，补充有粗细、长短和密度变化的边线、纹样与近看细节。机身、翼面、尾面、机腹和配件都有明确的图形职责，较安静区域也要属于主题。复杂作品可比较少量构图不同的缩略稿，依据实际轮廓选择。见 [美术设计](references/art-direction.md) 和 [线条与配色](references/linework-and-color.md)。
3. **实际分层编辑。** 使用可用的 Photoshop 或 Composa 接口完成导入、边缘处理、缩放旋转、选区、文字与调色。人物、文字、背景、结构和配件按职责分层，文字保持可编辑。操作见 [编辑工作流](references/editor-workflow.md)。
4. **处理原 UV 与材质。** 保留原 UV、比例、部件变换与材质分组，核对接缝、共享纹素和通道。分别规划主体涂层、角色印刷、装饰边条与机械金属的表面质感，区分亮漆和金属光泽，按需用区域遮罩调整相应通道。直接 UV 编辑或正交投射根据任务选择；正交图保持相机信息并按可见性回烘。见 [UV 与材质](references/materials-and-uv.md) 和 [正交制作](references/orthographic-workflow.md)。
5. **看模型并修订。** 检查顶底、两侧、前后和斜视中的人物识别、文字方向、配色、接缝、镜像与拉伸。先修可见问题，再根据反馈调整相关层。记录具体检查状态，不把平铺 atlas 当作模型效果。
6. **输出可用成果。** 交付可编辑工程、BLK 与实际贴图、模型预览和简洁说明，完成格式与配置检查。安装、游戏验证和发布按用户要求及项目约定执行。见 [打包与验证](references/packaging-and-validation.md)。

## 关键约束

- 读取 BLK 确定资源用途，保留 `name:t="user"`、精确资源名与所需 wildcard；自制目标必须对应真实包内文件。
- 模板可能是纯色或常量占位图。确认真实细节与材质后再作为基底，按实际资产核对改型兼容性。
- 颜色 RGB、颜色 alpha 与打包材质分别处理。只换图案时保留材质；用户要求或设计需要金属、亮漆等质感时落实到材质分区，只改对应区域和通道，保留未经修改的法线细节。不能用一层银灰底色代替明确的材质需求。
- 共享 UV 的多个表面共用像素。通过图案一致性、位置和投射优先级处理冲突，保持正反面与文字方向正确。
- Composa 以当前工具 schema 为准，保存 CMPS；DDS/TGA 和特殊通道由文件工具衔接。栅格化内容的可编辑范围如实说明。
- 图像模型的输出作为独立栅格素材导入。人物保护区域需要逐像素保留时，由编辑器从原图合成；指定模型通过实际模型参数选择。模型生成的高光、正交示意和文字不能直接充当材质通道、真实模型七视图或可编辑文字层。
- 按项目约定使用离线或游戏验证；明确禁止启动游戏时仅做离线检查。静态检查、预览结果和用户验收分别记录。

## 执行工具

| 脚本 | 用途与依赖 |
| --- | --- |
| `scripts/inspect_skins.py` | BLK/贴图检查；Python 3.10+，图片预览需 Pillow |
| `scripts/compare_skin.py` | 独立通道与 UV 覆盖区比较；Pillow、NumPy |
| `scripts/composa_mcp.py` | 当前 Composa 工具发现与顺序调用；Python 标准库 |
| `scripts/fetch_asset.py` | 获取已选图片并记录来源；requests、Pillow |
| `scripts/surface_preview.py` | 原 UV 几何预览与覆盖图回烘；NumPy、Pillow、Numba；prepare 另需配置资源解码器 |
| `scripts/build_skin.py` | 编辑器导出与确认过的原贴图组装 TGA/BLK 包；Pillow、NumPy |

工具服务于设计判断和编辑执行。需要查看参数时先用 `--help`；复杂步骤读对应参考，避免将所有流程强加给局部修订。
