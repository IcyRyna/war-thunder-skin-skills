# 战雷二次元喷气式飞机痛涂

按目标喷气式飞机与二次元角色或作品主题，制作实际可编辑、可继续修改的痛涂。由助手完成素材选择、构图判断、编辑操作、模型检查和打包交付。制作任务持续到一版实际成果，普通设计决定自行选择合理值。

## 执行范围与项目约定

适用对象是固定翼喷气式飞机，视觉主题是二次元角色、动漫或游戏作品。历史复原、无二次元主题的通用涂装，以及地面载具、直升机、舰船和螺旋桨飞机涂装，不属于本技能的执行范围。

先按当前请求选择工作：新作走完整链路；局部修订保留已接受部分，只补受影响的编辑、模型与交付检查；点评、选型和方案聚焦指定问题；格式检查或适配按实际改动验证。研究、学习或审计按 [研究与审计](references/research-and-audit.md) 收集证据、验证方法和更新规则，不自动开启新作品。明确“不重做”时保持已有作品。

有工作区和任务登记时，先按登记定位本次任务，再读取项目及该任务的 `.skin-workshop.json`。约定按“本技能默认 → 项目 → 当前任务 → 当前对话的明确覆盖”应用；后者未提及的字段继续继承，只加载已选任务的配置。配置记录需求，不产生用户豁免：代理写入的“安静细节”“不强制边框”等笼统表述，不能稀释用户已明确的三尺度线条、人物覆盖或完整性要求。核对覆盖变更的用户依据，不把实现方便当授权；普通未定项自行选合理值。

配置指向现用偏好或指定参考记录时，读取与本次工作相关的字段，并实际查看对应图片；其中的旧任务与历史状态不自动成为当前需求。整体美术参考、专项线条参考与角色素材分别辨认。用户已指定的参考关系优先于代理自行选择的角色图形语汇，不能只读取任务自拟方案便默认它已承接参考。

内部项目资料、配置、过程记录和非交付文件留在工作区。对外说明聚焦当前作品的设计、用法和验证结果。素材出处与所用素材的 credit 按实际要求保留。

## Agent 能力与素材来源

核心流程不依赖特定 Agent 品牌或模型供应商。按当前环境实际提供的文件、检索、图片查看、编辑器和模型工具执行；工具名、API 参数和安装发现方式遵循该环境。包内 Python 脚本是有相应运行条件时可用的辅助，`agents/openai.yaml` 是可选的界面元数据，其他 Agent 可直接使用本文件及对应参考。

先查看当前工具列表、连接服务与已配置程序，区分纯文本生图、原图/遮罩编辑和透明输出。按实际接口确认能力与模型选择，不根据 Agent 品牌猜测，不通过试生成或擅自安装服务检查能力。工具能确定时按结果执行；无法检索或仍不明确时，用一个简短问题询问用户是否有可用图像工具，同时继续检查已有素材。用户指定的原图、模型与制作路线优先。

素材按“用户给图或指定原图 → 本项目已有适用素材 → Agent 自主联网检索并取得实际原图”选择。没有图像模型时，使用编辑器抠图、调色、形状与文字层继续制作；模型是可选分支。不能联网时检查前两类来源，只有关键原图仍无法取得时才说明具体缺口并请求补充。普通找图由 Agent 完成。具体选图与编辑方法见 [素材与布局](references/assets-and-layout.md)。

## 美术验收与作品留存

技术检查通过只说明格式、配置或制作步骤满足对应条件。成功作品必须有用户的实际美术认可；自评分、工程数量和打包结果不能代替验收。用户只作有保留的认可时，记录其程度与限定，不提升为优秀范本或成熟能力证明。

技术合规、基本识别与构图、美术评价分别记录。头型或动作损坏、指定表面缺人物、明确要求的底色洁净度、表面质感或参考线条关系未满足时，基本验收应失败；不能用“格式正确、脸还可认、没有误涂”放行。已知且能离线修正的缺陷不能改称受限候选来关闭修订，也不能以用户美术评价待定替代必需项修正。用户否定版本后将其登记为失败反例；独立审查的肯定与实物或用户反馈冲突时，复查具体漏检，不以审查人数维持原结论。

局部修订先区分已接受部分、仅完成数据检查的部分和已知未解决缺陷。为控制变量沿用旧数据时，在新验收中保留尚未解决的失败项及证据；局部改善或重新限定检查范围不能将其改为通过。配置中的 preserve、verified 或 resolution-only 只描述操作范围，不构成用户豁免；当前请求涉及的线条或质感问题须进入本次对应检查。

按项目约定维护当前作品索引，只展示已获认可的作品并注明认可程度。明确失败的作品退出当前作品区，按用户要求集中归档；保留其实际评价，避免在后续任务中继续当作成功示例。归档时先保护仍被当前作品使用的共享资源，再校验归档完整性。

## 制作流程

1. **确认图片工具能力。** 按上一节先检索生图与原图编辑能力；信息不足时简短询问用户。记录实际可用的制作路线，再按需使用图像模型或现有素材与编辑器。
2. **确定素材与承载面。** 核对改型、角色版本与原图来源，在真实连续表面上试放完整头型、主要发型与头饰，以及所选姿态需要的颈肩、肩臂、手与道具关系。先保住这些关系，再决定远端衣摆、长发尾与肢体的有意裁切；五官没断不代表整体成立。比较换姿态、位置、角度、尺度或承载面，不能只为放大脸而持续削掉头部与动作。完整性和主视觉重量分别验收：完整且可认不能关闭“立绘仍小”的问题，主视觉任务需在同模型、同相机和同机体显示尺寸下比较明显更大的可行候选。编辑器负责抠图、调色与组合，图像模型按实际需要可选使用。见 [素材与布局](references/assets-and-layout.md) 和 [图像辅助编辑](references/image-assisted-editing.md)。
3. **组织整机关系。** 先锁定当前 brief 的逐面人物、文字和图形职责，再安排大形与连接；通用的“人物配文字翼”选项不能替换已指定的双翼人物。用户明确要求机背主路径、中等轮廓与细线节奏时，按座舱后、翼根和后机身逐项落实，宽色场不能自动代替缺失尺度；其他任务按实际主次决定密度。单垂尾默认左右两面均安排适配肖像，双垂尾默认外侧人物、内侧图形；核对面别、共享 UV 与文字方向。机腹与主翼下默认不放人物。复杂作品比较少量构图不同的候选。见 [美术设计](references/art-direction.md) 和 [线条与配色](references/linework-and-color.md)。
4. **实际分层编辑。** 使用可用的 Photoshop、Composa 或其他支持所需操作的分层编辑器完成导入、边缘处理、缩放旋转、选区、文字与调色。人物、文字、背景、结构和配件按职责分层，文字保持可编辑。新作或换底时，先按 [UV 与材质](references/materials-and-uv.md) 确认重涂域与通道，输出仅含新底色与必要结构的平光及受光模型试片；旧涂层污染未解决时不进入图文细化。局部修订只复查受影响域。操作见 [编辑工作流](references/editor-workflow.md)。
5. **处理原 UV 与材质。** 保留原 UV、比例、部件变换与材质分组，核对接缝、共享纹素和通道。分别规划主体涂层、角色印刷、装饰边条与机械金属的表面质感，区分亮漆和金属光泽，按需用区域遮罩调整相应通道。直接 UV 编辑或正交投射根据任务选择；正交图保持相机信息并按可见性回烘。见 [UV 与材质](references/materials-and-uv.md) 和 [正交制作](references/orthographic-workflow.md)。
6. **看模型并修订。** 检查顶底、两侧、前后和斜视中的识别、文字、配色、接缝、镜像与拉伸，按实际单尾／双尾结构检查各面职责及机腹、翼下。在细化前隐藏人物检查翼面和垂尾的浅深色场与中尺度组织，恢复人物后再检查主视觉重量、头型动作及图形竞争；边缘深色线组完成不能代替中央浅色区的构图。为当前必需表面和要求登记 `pass`、`fail` 或 `uninspected` 及证据；失败先修，能补看的必需项必须补视角。确实无法检查时可交付受限候选，总体不得标全通过。正交完整而斜视碎裂的候选退回布局；平铺 atlas 不替代模型效果。
7. **输出可用成果。** 交付可编辑工程、BLK 与实际贴图、模型预览和简洁说明，完成格式与配置检查。安装、游戏验证和发布按用户要求及项目约定执行。见 [打包与验证](references/packaging-and-validation.md)。

## 关键约束

- 读取 BLK 确定资源用途，保留 `name:t="user"`、精确资源名与所需 wildcard；自制目标必须对应真实包内文件。
- 模板可能是纯色或常量占位图。确认真实细节与材质后再作为基底，按实际资产核对改型兼容性。
- 颜色 RGB、颜色 alpha 与打包材质分别处理。以已确认材质为基底；改动人物位置、尺寸或裁切时，检查原材质是否包含依赖旧图案的分区，并同步修正受影响的印刷、涂层与金属遮罩。均匀且不依赖图案的材质可保留；需要金属、亮漆等质感时按区域修改对应通道；法线中的机械结构与旧涂层凹凸分别确认，按明确遮罩保持、清理或重建，不能以全量原样保留代替干净新漆检查。不能用一层银灰底色代替明确的材质需求。
- 共享 UV 的多个表面共用像素。通过图案一致性、位置和投射优先级处理冲突，保持正反面与文字方向正确。
- 人物需要显眼，但不得用头型、发型头饰或肩臂动态的损坏换取面积。选择合适头像、半身与裁切，在连续面保住完整识别和动作，再安排外围出画；整幅 alpha 命中与脸部命中都不能单独决定尺寸。投射可见性只能防止误涂，不能修复构图。单尾左右面与双尾内外面分别处理，当前用户要求优先于默认分工。
- 使用 Composa 时按当前工具 schema 操作并保存 CMPS；使用其他编辑器时保存其原生可编辑工程。DDS/TGA 和特殊通道由实际支持的工具衔接，栅格化内容的可编辑范围如实说明。
- 用户给图、检索原图与模型衍生图保留来源关系；原图独立保存。图像模型可用时，输出作为独立栅格素材导入，指定模型通过实际参数选择。人物保护区域需要逐像素保留时，由编辑器从原图合成；模型生成的高光、正交示意和文字不能直接充当材质通道、真实模型七视图或可编辑文字层。
- 按项目约定使用离线或游戏验证；明确禁止启动游戏时仅做离线检查。静态检查、预览结果和用户验收分别记录。

## 可选执行辅助

| 脚本 | 用途与依赖 |
| --- | --- |
| `scripts/inspect_skins.py` | BLK/贴图检查；Python 3.10+，图片预览需 Pillow |
| `scripts/compare_skin.py` | 独立通道与 UV 覆盖区比较；Pillow、NumPy |
| `scripts/composa_mcp.py` | 当前 Composa 工具发现与顺序调用；Python 标准库 |
| `scripts/fetch_asset.py` | 获取已选图片并记录来源；requests、Pillow |
| `scripts/surface_preview.py` | 原 UV 几何预览与覆盖图回烘；NumPy、Pillow、Numba；prepare 另需配置资源解码器 |
| `scripts/scene_preview.py` | 标准解码导出组装多材质整机场景、补充相机及近似材质预览；NumPy、Pillow、Numba |
| `scripts/finish_preview.py` | 显式通道 profile、两完整环境与法线隔离的近似材质对照；NumPy、Pillow、Numba |
| `scripts/build_skin.py` | 编辑器导出与确认过的原贴图组装 TGA/BLK 包；Pillow、NumPy |
| `scripts/dds_variant.py` | 从 TGA 包另建 DDS 与实际 mip 对照；Pillow、NumPy，另需受支持的官方 texconv |

工具服务于设计判断和编辑执行，按当前环境的接口与依赖选择；不要求特定模型工具。需要查看脚本参数时先用 `--help`；复杂步骤读对应参考，避免将所有流程强加给局部修订。
