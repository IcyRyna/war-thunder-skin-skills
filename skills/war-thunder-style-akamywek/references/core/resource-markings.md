# 从真实资源制作飞机标记

飞机小图标、剪影是有机型、有视角的素材，不是随手凑出的装饰。先认清是侧视、俯视还是立体视角，再找对应机型的游戏资源；不能拿一架近似飞机的手绘轮廓代替，也不能把近似图说成原图。

## 查找与确认

1. **先确认资源 ID。** 从 BLK、模型和当前任务确认载具 ID。显示名和文件名可能不同：F-2A 是 `f_2a`，不是美军螺旋桨机 `f2a-1`；模型（DynModel）又叫 `f2a`。
2. **只读检索本机游戏 UI 包。** 不启动游戏、不改安装文件，资源只输出到当前任务。F-2A 的俯视矢量图在 `ui/atlases.vromfs.bin` 的 `gameuiskin/f_2a_ico.svg`；同包的 `units/f_2a.ddsx` 是彩色立体小图，`ui/tex.vromfs.bin` 的 `aircrafts/f_2a.avif` 是彩色机体卡片。文件名像不代表视角和用途一样，打开看实际内容。解包器的大小或格式限制是工具限制，不等于包里没有。
3. **记录来源。** SVG 按原路径高分辨率渲染（透明底），记下包名、包内路径、渲染方式和 SHA-256；之后只处理透明边、颜色、朝向和尺度。

## 和参考作品对上

学别人的作品时，先把游戏图标和作者画的图标配准，看是不是同一个来源：

- `replica_measure.py icon --icon <渲染的 PNG> --rotate <让机头朝向一致的角度>`：按重叠最大拟合缩放、旋转和位置，报告重合度，并按作者图量出渐变（起止占图标长度的比例）和投影（偏移、颜色）。
- F-2A 实测：平尾两枚和左下一枚签名色飞机都是 `f_2a_ico`，重合 0.96；渐变是作者共用的 #8d2a28 → #bd3744（21–23% / 75–81%）；平尾两枚有一层向下 11 px、#523131 的暗红投影，左下那枚没有。投影的 R 可能低于红色类别阈值，要按“既不是涂层也不是图标本体”去找。
- 重合度高，才能说“作者用的是游戏图标，我们用同一个位图”，标为**位图复用**；轮廓是游戏的，颜色和位置是测出来的。

## 找不到同款时

- 如实记录“未找到同款”，写清搜过哪些包和名称模式。
- 可以由对应机型的原模型生成所需正投影：写明节点和挂载状态，按可见三角生成透明轮廓，座舱玻璃单独处理。标为**游戏模型派生**，不能说成参考作者用的原图。F-2A 背部的侧视剪影就是这种情况：游戏 UI 包里没有侧视剪影，作者的剪影与模型右视投影只重合 0.80（垂尾后掠、座舱鼓包不同）。
- 照作者的轮廓描出来，是**源轮廓临摹**，只能用于研究复刻，并照实标注。
- 不要退回近似手绘飞机。

## 放到原 UV

- 用 `vector_paint.py` 的图像图层放透明 PNG：`source`、`chart`、`center`、米制 `width`、`rotation`，必要时 `flip`。俯视图和侧视图分别确认机头朝向、垂尾朝内还是朝外、左右镜像；`flip` 不是“左侧必开”的规则，要看实际模型。
- 研究复刻里也可以把配准好的图标（`icon` 输出的 `placed.png`）直接按 atlas 位置合到最终颜色图上（`replica_check.py assemble --icon`）。
- 机背曲面会让展开图比例和俯视投影比例不同；在平面图表里补偿时记录每个轴的比例，保留未变形的原件。不能把抻长、压扁后“碰巧像”当成机型核对。
- 最后看实际模型近景和最终贴图的原像素裁片：翼形、进气口、垂尾、座舱、天线，和文字之间的间距。图标来源、几何重建和字体替代分别记录；游戏原素材不适用脚本或字体的许可证。
