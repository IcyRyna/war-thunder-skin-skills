# 旧经验迁移

用于重构已有 Skill 或整理长期积累的案例。先分离规则的归属与证据强度，再决定保留、缩小范围、重测或撤回；不因文件多就丢弃有效工具，也不因过去发布过就认为内容已验证。

## 四类内容分别处理

| 旧内容 | 迁移目的地 | 保留前的核对 |
| --- | --- | --- |
| 可复用工具与工程不变量 | 通用核心 | 实际调用者、输入输出契约、适用目标、回归与已知限制 |
| 视觉关系和风格配方 | 对应风格模块 | 依据来自哪件作品、哪个分支、哪些用户反馈；是否被误写成通用美学 |
| UV、部件、遮罩与材质映射 | 对应载具 profile | 模板版本、原资源、共享关系、测量方法与实际确认范围 |
| 参考、失败、评价和试验过程 | 研究证据与回归案例 | 原版本、原哈希、来源及评价边界；有无混入事后解释 |

不能仅凭旧文档一句“已验证”晋升。追到真实输入、输出和检查证据；找不到时保留原记录，并把本轮可确认状态写成证据不足。不得改写历史日志来使它符合新 schema。

## 值得保留的工程经验

检查现有实现是否已经提供：原资源只读保护、原 UV 合约、共享纹素处理、可编辑源、参数与产物对应、原尺寸细节检查、模型多视图、导出与配置检查、实际游戏验证、作品与技术状态分离。

这些机制可作为新工作流的基础。迁移时保留可运行入口、必要测试与实际依赖；不把全部工具重写当作流程改进的前提。冻结的历史脚本只作证据，不能直接恢复为现用入口。

## 需要缩小范围的经验

特别检查以下叙述：

- 从一件作品推导所有风格的配色比例、线宽、材质值、字号或分辨率。
- 把当前用户偏好当成所有用户的审美要求。
- 把某个载具表面或 UV 的处理固定成所有机型的规则。
- 把参考测量重建说成独立构形，把截图观察说成作者制作方法。
- 把离线近似材质预览说成游戏实际表现。
- 把一次完成、很多自动指标或代理自评说成稳定自主创作能力。

有效数据不必丢掉：将它们改为明确范围的来源观察、候选参数或回归案例。尺寸数字保留测量分母、分辨率或物理尺度；只知道某次输出有效时，不扩成普适区间。

## 保留用户评价的边界

从已认可版本的实际预览和设计源提取经验，而不只读汇总结论。整体认可可作整体参照；局部认可只支持该部位或属性。用户同时认可线条与布局、否定文字时，分别保留，不让公开“已认可”标签抹掉缺陷。

否定案例仍有价值，但先查明具体原因。没有具体反馈时，它只证明该版本未获认可，不证明某一算法或颜色必然错误。缺少可编辑源的正例可以提供外观证据，不能自动提供可复现制作流程。

## 迁移顺序

先为实际需要变更的规则建立证据映射并冻结旧版，保留已有工具和作品原字节。用一个明确案例检验新的记录与评测流程，再扩展到其余规则。每批迁移记录旧位置、去向和身份；调整现用路径与登记，冻结历史引用使用可追溯迁移映射。

用对照结果决定是否替换旧版。流程重构可以先成立，风格能力仍可能未验证；这两个结论应同时保留。
