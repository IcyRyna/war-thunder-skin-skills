# 记录契约

用于参考分析、规则提议、载具适配和评价入库。字段类型、机器枚举及命令以项目实际 schema 和工具 `--help` 为准；这里规定字段必须表达的事实，不另建一套有冲突的格式。项目尚无 schema 时先用普通结构化记录表达这些事实，随后再映射；不能凭空编造哈希、已验证身份或状态命令。

## 规则最小信息

| 顶层字段 | 必须能回答的问题 |
| --- | --- |
| `id` | 哪一条持续追踪的规则？修改内容保留身份，改变研究问题则建立新规则。 |
| `scope` | 适用于何种风格、载具家族、语义区域、平台或任务阶段？已验证范围与拟探索范围分开；例外是什么？ |
| `claim` | 在什么条件下执行什么动作，保留什么关系，怎样判断满足？属于工程约束、风格关系、参数、允许变体，还是仅供研究的假设？ |
| `evidence` | 支持、反对或限制该规则的材料与实验是什么？引用实际证据 ID、文件和对应版本，不能只贴来源首页。 |
| `validation` | 哪些检查真实执行，结果如何，适用条件是什么？哪些未测？技术、视觉、游戏、复现分开。 |
| `review` | 谁在何时对哪个版本、哪个部分作了什么判断？用户评价、代理建议及发布授权各自是什么？ |

规则文本应能用于执行和否证。“更高级”“像作者”只够表达目标，不能独立成为操作规范。可以写“指定阅读视距中，主字与背景可区分且不会与邻近图形合成另一字形”，然后说明观察视图和检查方法；无需为此虚构一个对所有载具通用的最小字号。

## 证据层次与身份

每份材料注明一种来源身份；同一材料产生不同结论时分别记录推理过程。

| 类型 | 可以支持 | 不能自动支持 |
| --- | --- | --- |
| 来源观察 | 实际可见形状、位置、文件结构和通道数值 | 未见反面、作者意图、图层顺序、某个数值在游戏中的外观 |
| 制作假设 | 一个待实验的机制、视觉关系或适配策略 | 已经验证、作者实际用了这种方法 |
| 受控实验 | 本次输入、变量、工具与观察条件下的结果 | 未测试载具、其他主题、长期成功率 |
| 实际游戏证据 | 对应导出包在记录环境和视图下的显示 | 所有视图或未来游戏版本都正常 |
| 评价记录 | 评价者针对明确版本与范围的判断 | 未提及部分也获认可，或通过技术检查就获审美认可 |

证据记录至少包含：来源身份、作者或执行者、取得日期、原始出处、文件或截图位置、版本与哈希、实际观察范围、能支持的结论和限制。来源的发布日、更新日与本次查看日分别保留。不能打开或没看过的内容写未核实。

同一作品的多张图、换色、轻微修订和语言镜像页属于一个来源组。分组依据保留，无法判断时标记可能重复，不把它们算成多个独立成功样本。授权记录与研究判断分开：可阅读的参考不自动成为可再分发资产。

## 语义区域接口

风格规则描述视觉职责；profile 解析具体承载面。语义名由任务选取，不强制把飞机和坦克压成同一组部位名称。

每个需要实际落地的区域应能找到：

- 视觉职责、必需性，以及没有该区域时的退让规则。
- 载具与部件身份、纹理角色、遮罩或几何选择、坐标约定和朝向。
- 共享纹素、镜像、接缝、形变、遮挡与活动状态的约束。
- 测量空间和尺度，比例的分母是否为有效遮罩、标准视图可见面积或物理宽度。
- 映射证据及验证状态；离线模型确认和游戏确认分别记载。

例如“主焦点放在最大的连续上表面”允许不同机型得到不同实际位置。若该面被结构切断，应按规则选另一个完整区域、拆分图形或明确说明无法满足；不能自行把“主焦点完整”降为“任意可见片段”。

通道解释、导出参数、具体 UV 坐标与模板版本放 profile 或实验参数。风格只写期望外观；已测参数可以作为注明范围的配方引用，不提升成所有载具的事实。

## 状态与评价

每个验证门分别使用实际 schema 的状态，表达以下五种事实：通过、有证据失败、未执行、证据不足、不适用。后三种均不能被解释为通过；不适用要有任务依据。

评价记录定位到产物清单或明确文件哈希，并区分：

- 整体认可。
- 局部认可：精确列出部位、属性及保留要求。
- 有例外的认可：同时保留认可项和否定项。
- 否定或待评价：没有原因时保留未知，不编造失败机制。

一个规则可已有来源观察但尚无实验；一个成品可技术通过而视觉未通过；一个用户认可的成品也可能尚无可编辑源或独立复现记录。这些状态可以并存，不压成单一“成功”字段。
