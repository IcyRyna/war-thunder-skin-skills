# 实验与评测

用于检验候选规则、确认 Skill 改动是否有收益，以及决定可声明的适用范围。按研究问题选择必要试验；不强制每次局部修订执行全部矩阵。

## 先冻结再运行

记录问题、假设、反证条件、基线、唯一主要变量、输入身份、输出要求、评判方法及停止条件。已有验收要求沿用；需要新阈值时在见到结果之前确定并标记依据。样本数量取决于所要检验的变化来源和实际成本，没有固定的通用及格次数。

冻结输入包括 Skill/规则、profile、素材、完整 brief、工具与可记录的模型版本、可控参数、相机、展示尺度、输出设置和量表。记录不可控因素；工具不支持种子时写明不支持。哈希用于识别输入和输出，不充当效果评分。

把来源组分配为研究、调参、回归或留出评测。冻结记录保留每组身份和分组理由。留出材料由评测方保管，执行者只获得正常生产所需信息和公开的验收条件。冻结后才开始提炼；事后切分已经看过并据此调整的资料，不能成为真正未见的留出集。

## 最小受控实验

1. 保存未经修改的基线及相关输入。
2. 仅改变问题涉及的一项主要变量，记录实际操作和参数。若联动不可避免，列出联动项，将结果标为组合效果。
3. 检查变化在最终输出中确实存在；配置文件写了新参数而最终输出未变化，不能形成有效对照。
4. 在相同视图、尺度和观察条件下比较。源贴图、原尺寸细节、模型视图、游戏画面分别回答不同问题。
5. 记录收益、退化、无法判断的地方及其他可能解释。每个输出都保留，不能只选择最好的一张。
6. 只修订结果支持的范围。将失败归因于资料、风格规则、profile、工具、导出或游戏表现；无法分辨时标记待诊断。

材质实验固定颜色、几何、纹理映射和观察条件；构图实验固定素材和材质；配色实验固定布局和测量分母。不要同时换主体图、改色、改材质再把改善归于某个线宽。

## 测试矩阵

| 测试 | 固定项 | 改变项 | 能回答的问题 |
| --- | --- | --- | --- |
| 工程重建 | 源文件、工具、所有可控参数 | 新工作副本或独立执行环境 | 工程链路能否重建，变化来自哪里 |
| 同 brief 独立重复 | 同一完整 brief、输入、规则、profile、工具和随机性策略 | 新会话，记录实际随机因素 | 是否依赖隐藏聊天、临场补丁或挑选结果 |
| 允许变体 | 已验证 profile、核心规则、工具和冻结标准 | 预先约定的主题、编号或素材等可变项 | 能否保留核心关系并容纳新内容 |
| 同类载具迁移 | 风格、相近任务难度、工具和标准 | 未用于调参的新载具及其独立 profile | 语义关系能否适应新表面 |
| 基线 A/B | brief、profile、通用制作能力、可控工具条件与成本约定 | 明确的风格模块或候选规则 | 新模块相对基线增加了什么 |
| 边界案例 | 核心规则与实际工程能力 | 规则声称可处理的受限区域、共享 UV 或缺失锚点 | 退让策略是否真实可执行 |

同 brief 重复不能更换涂装中的编号、主题或已指定种子；这些分别属于变体或种子试验。产物版本号、运行 ID 和输出目录应该各自独立，这些记录身份变化不改变 brief。工具没有种子控制时，各次采用相同策略并记录随机性。复制同一产物不能算独立运行。

迁移先验证新载具 profile 的基本工程，避免把错误模板归因于风格；输入可以包含新载具的 UV 与遮罩，但不能提供该载具在目标风格下的预制答案。飞机到坦克属于跨类别探索，不能由两架飞机的通过结果直接推导。

## A/B 的解释

明确比较单位后再组装执行包：

- 比较整套风格包：A 使用原有通用制作能力和同样的目标描述；B 增加具体风格规范及其专用资产。所得结论只说明整个模块的增益。
- 比较规则文本：两组获得相同素材与工具，只让 B 获得提炼后的规则或步骤。
- 比较一次修订：A 使用旧规则，B 使用候选规则，其余条件冻结。

使用独立上下文，保存两组所有首次结果、修改和人工干预。需要主观评判时采用中性文件标识，评审前不透露哪个是候选或预期赢家。评分标准必须向执行者公开；隐藏的是答案、身份标签和事后反馈。

比较首次达标、最终达标、修改次数、人工介入与具体退化。一次 A/B 偏好不能推出长期成功率，也不能把整包优势全部归功于 `SKILL.md` 文字。

## 四类验证门

| 门 | 通过依据 | 边界 |
| --- | --- | --- |
| `technical` | 文件和引用可读，输入匹配，导出约定、资源完整性和必要重开检查有实际证据 | 静态格式检查不证明风格或游戏表现 |
| `visual` | 指定视图、原尺寸与使用尺度中，当前规则和用户要求逐项满足；评价指向实际版本 | 代理视觉评估不能代替所需的用户审查 |
| `game` | 导出包与真实游戏记录对应，规定视图、材质、接缝与适用活动状态已检查 | 离线近似渲染、生成展示图不算游戏证据 |
| `reproducibility` | 独立运行记录、输入清单、完整尝试与实际结果支持所声明的重复或迁移范围 | 单次成功和字节相同都不证明跨任务稳定 |

技术错误先处理；视觉问题可以并行观察，但不能以高审美分抵消。没有游戏访问时交付可加载候选与检查清单，将 `game` 留为未运行，继续其余可执行检查。

## 反馈与留出集退役

评测者提交原始判断后才展示身份和诊断。凡用于修改规则的留出案例转入调参或回归，保留转移原因；下一次泛化判断需要新的未见案例。只有复查完全未改动的证据时才能继承原检查事实，原来失败或未测的项不会随之关闭。

规则、工具或量表变更时，重跑受影响测试及必要回归。量表改变要保留新旧尺度的结果，不能将两者直接合并。结论报告实际测试条件、运行数、全部失败与限制；无需用无依据的百分比描述“稳定”。
