# 终末地工业涂装

把车辆组织成可信的工业设备：大明暗建立体量，完整工业徽记建立身份，黄色路线建立方向，成组设备信息建立尺度。A7V 是第一视觉范本，A7HU 是同家族适配案例，EMBT 是混合资源与异形炮塔案例。它们是已见研究材料，不是三次独立泛化验证。

0.2.0 为**发布候选**：已完成来源研究、原生表面局部效果比较与独立包检查；独立复现尚未回传，游戏实测未运行。先读[验证范围与缺口](references/validation.md)。其方法按「来源观察 → 条件化规则 → 目标车语义映射 → 分层制作 → 原尺寸与模型检查」组织。构图读[构图与反例](references/composition.md)，理解来源时读[三套范本](references/source-cases.md)；规则身份、证据与待测范围见 [rules.json](references/rules.json)。工具不替你完成构图。

## 先确定这辆车怎么读

1. 核对用户指定的型号、附件状态、当前模型、材质槽、颜色图、N、AO 和 BLK。给输入记录哈希。先认真实承载面，再画色块；新车的 [profile](references/vehicle-profile.md) 决定实际 UV、方向、共享纹素和保护区，不从外形相似推断兼容。
2. 分配四种视觉职责：**主识别面、次识别面、方向延伸面、安静机械面**。车体、炮塔、炮管、武器站、附件和轮履分别决定职责，可以缺省。不要为了填满一张分区表而给每块装甲加图案。 对有足够长度的主识别侧面，先给主徽记、方向黄带、设备／三色微标分别指定主要区域，留出连续底色；不要把全套元素自动塞进同一处。紧凑的次识别设备模块可以成组，但不能把它的布局放大当整块侧面的构图。
3. 在主要阅读角度先排黑／灰白大区，再留主徽记的完整阅读空间，再画主黄带和伴线，最后安排设备模块与低对比纹样。暗顶、浅肩、深侧裙是 A7V 的有效分支；新车允许改变各区，保持主次，不锁黑白百分比、徽记像素尺寸、V 形车首或 U 形车尾。
4. 给左右两侧各排正向文字。共享或镜像 UV 无法容纳独立文字时，改用对称图形、迁到独立面或取消该处文字，并说明取舍。炮塔／车体、炮塔／炮管会运动，方向呼应即可；不用静止视图强制连成一根线。

## 用包内透明素材制作

先看[素材选择与编辑](references/assets.md)和 [assets/catalog.json](assets/catalog.json)。包内 PNG 为实际 RGBA，SVG 是可编辑母版；棋盘格只用于检查预览，不烘焙进素材。

- **完整工业徽记**保留三角、轮廓和 ENDFIELD／INDUSTRIES 的整体关系。使用整张透明母版统一缩放平移，靠车身底色提供对比。不得拆字、横向拉伸、裁掉小字或附加独立不透明贴纸底板。低分辨率原件不凭画布尺寸判断清晰度；大面使用包内已注明来源的矢量／高分辨率版本。
- **黄色路径**先定一条主方向，再安排宽色面、圆端／节点与细伴线。**炮塔侧面使用单一方向的直线黄带，可顺真实上缘倾斜；不画曲折、折线，也不把“直”误当“水平”。** 黄带可以等宽成组，主次由完整信息组的尺度、位置和对比建立，不强制一粗一细。 包内折转组件仅供其他合适部位重画参考，不用于炮塔侧面。各部件重画，不能把组件原尺寸当线宽规范，也不把每块板描一圈黄边。
- **身份与微字**分级排版。设备编号、车型铭牌改成本车信息；品牌字形使用母版。一个主面里先保住主标，再给中、小模块空间。不要把模板中的 VEHICLE／01 当最终车型。
- **低对比纹样**服务局部色场与安静区。先给品牌与设备文字保留独立阅读区，再设计纹样路径和自然终点；保留原样 RGB／Alpha 的低对比纹样经真实阅读检查可以采用；不能只凭低透明度宣称通过，也不能裁掉主标周围一块就算完成。分层工程中先背景纹样，再路线、品牌和设备信息；平面合成不能代替语义保护区。见[本轮真实失败与边界](references/observed-failures.md)。轮廓线、三角网络、十字／刻度与微量辅彩按需选择，不要求每车用全套。

透明叠加层与最终固定替换颜色图的 Alpha 含义不同。先在图层中排版，再按该材质的通道契约合成；不要把颜色图全零 Alpha 误当“图全透明”。工程步骤和命令见[制作工具](references/production.md)。

## 原生 UV 与材质落实

用当前可用的编辑器和实时接口，保持可编辑层：本车机械基底、明暗底漆、黄色主次路径、品牌、设备信息、纹样、可选表面效果。默认 `weathering=none`、`surface_grain=none`；用户指定时分别开启。机械结构、AO、掉漆、材料光泽与噪点分开判断。

在真实模型确认节点、材质槽和 UV 岛 → 在同一原尺寸图集以 1:1 查看 → 修改 → 重载同一模型复查。每次记录同一部件和资源身份。检查共享岛、旋转、镜像、跨板接缝、炮盾曲面、附件遮挡和其他使用同一图集的部位。模型负责定位和最终可见关系，平面 UV 负责像素与数据，两者成对核对。

固定装甲、透明网格、橡胶、玻璃和 packed N 各有语义；EMBT 的 `embt_alpha` 不得沿用固定装甲的 Alpha 策略。混合车型按实际槽逐项绑定，不把 A7V 车体复用扩成整车 UV 相同。读[贴图与材料](references/texture-contract.md)，使用随包工程工具；没有明确通道来源时保留已核实值，不猜粗糙度或金属度。

## 检查与交付

- **整体：** 黑白大区是否清楚，主标是否完整，黄色是否导向，密集模块旁是否留出安静面。以本车主要阅读角度判断，不能用 UV 空白面积统计整车配色。
- **局部：** 主标字形、文字方向、牌号、黄带端点和接缝在目标阅读尺度与必要的 1:1 局部都可读；开口、灯具、格栅、橡胶和网格保持本车结构。带旧车孔口／阴影／AO 的参考裁片只用来观察。
- **输出：** 从最终 DDS 解码读回，再重载实际模型；核对 BLK、资源数量、尺寸、颜色、Alpha、数据通道与完整 mip 到 1×1。源工程用副本重开，保留既有编辑器文档。
- **结论：** 分开记录技术、代理视觉、用户评价、游戏实测和独立重复／迁移。作者截图与离线预览不算新作游戏通过。未做写 `not_run`，失败和人工修补如实保留。

交付本次实际制作的游戏运行文件和可编辑源；研究图板、评测答案与模型不用塞进游戏 ZIP。七视图、安装或发布按本次用户授权；普通制作优先局部模型预览。大量图片读[图片输入与体积预算](references/image-input-workflow.md)：单批图像估算编码负载小于 **18,000,000 字节**，优先远低于此值；原图与生产数据不因此降精度。脚本统一 `python -B`，缓存放会话 TEMP。

本包自包含，不要求安装旧 Skill；没有携带游戏模型、编辑器、texconv 或已退役运行时。新整车的审美稳定性、游戏效果和未见车型迁移仍需实际验证，见[验证范围](references/validation.md)。
