# 部件、子区与全车任务书

先给全车一个意图，再让各部位发挥。可编辑源为 [zone-tree.json](layout/zone-tree.json) 与 [part-brief-contract.json](layout/part-brief-contract.json)；实际形态从各车型原始四视判断。这 29 区是便于讨论的语义区，不是要求每车恰好有 29 区，更不是现成涂色遮罩。

| 部件 | 示例子区 | 设计时解决什么 |
|---|---|---|
| H 车体，8 区 | 上／下前甲、前甲板、左右侧裙、动力甲板、尾面、单片侧板 | 主识别和主要色块；侧面可按实物板件再细分 |
| T 炮塔，8 区 | 左右前颊、左右侧／尾舱侧、前肩、乘员顶、尾顶、炮盾过渡 | 次识别、明暗体量、留白；不与车体重复抢主视觉 |
| G 炮管，4 区 | 护套、连接环、炮口、根部软套 | 长轴节奏、可读方向、材料分段 |
| M 机枪／座，3 区 | 外壳、底座、枪管与光学／机构 | 小尺度处理与设备可读性，可省装饰 |
| A 附件，4 区 | ERA／附加装甲、工具箱、网架／缆索、可选油桶 | 跟随邻区，保留孔隙；不存在的部件不用 |
| R 轮履，2 区 | 负重轮、履带悬挂 | 机械低层级，避免另做一个主海报 |

H04、T01、T02 是左右子区的合称。H07 表示把 H04 的实际侧面进一步按板件细分；选择一个工作粒度，不能同时安排两个重叠写入。实际任务给每片表面、共享参数和当前 Composa 文档一个写入者；单个执行者即可完成全车，本契约不要求或启动子代理。

全车任务书先写：要保留的范本关系、第一焦点／次级信息、色彩与材质角色、黄色职责、疏密、具体型号和附件状态。部件任务书再写：实际区域、它在整车的作用、本部位自由构图意图、可用素材、结构与 UV 限制、需要检查的相邻界面和 PS／模型证据。先讨论主次，再画子区，不先挑一套固定图案填所有格子。

一个部位可以主要留白，也可以完全不用某组素材。未知或共享 UV 先标为待定位，不把诊断色图视作已验证边界。跨面图案先看三维邻接和采样足迹；炮塔旋转、炮管俯仰后仍要成立，不能只在静止侧视拼成一条线。

使用 `scripts/layout_brief.py create` 可按家族生成 JSON 工作底稿。默认 `preset=null`；普通主题、编号、辅助文本是可改字段，主徽记本身不是任意可编辑文字。`check` 只检查接口与区域分配一致性，不评定美术质量。
