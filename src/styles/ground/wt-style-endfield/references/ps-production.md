# PS/Composa 与 Blender 配合制作和检查

先读[模型与UV双向对照](model-uv-cross-check.md)。在Blender确认真实构件及其材质/UV对应，在PS类MCP中看原尺寸纹素；修改后回模型复查。两者贯穿定位、制作和最终DDS读回，不只在末尾各看一张图。

只用 MCP 编辑器接口。首次运行 `scripts/composa_mcp.py --out NEW_SESSION_DIR --timeout 60` 读取实时 tools schema，再按 schema 取得文档列表，记录已有文档保护集合；工具或文档 ID 不从旧日志抄来。客户端不会替用户开启 AI Control，也不会自动重放失败调用；MCP 没有提供关闭文档时请用户处理本任务的标签，不控制桌面。

## 先试三个代表局部，再展开整车

先从范本关系中提出要验证的构图：炮塔顶／肩的图文、车体裙板的黄方向面、前装甲徽记与分板边缘。用相同输入、相机和观察尺度对照有无规则的方案，记录改善、退步与未定项；不把历史 A7V 临摹修复当成这次新设计的验证。

每个实际图集建立原尺寸工作文档；原作参考、本车结构、当前色块、图形、文字徽记、颗粒、可选做旧、诊断标注分层。原作和 r11 若需对照各自独立，不能把 r11 变成底图生产输入。全车先看明暗、焦点、黄色职责和负形，再以 1:1 局部检查：裙板、前甲倒角、炮塔顶字、侧标、尾部、轮缘、炮管与机枪座。每次单个细节裁区不超过 2048×2048，整图看缩略总览。

核对整体工业徽记是否完整、图层遮罩是否剪掉三角或字脚，检查反向／分割文字、笔画与间距、线宽、共享 UV、跨板连续性、孔壁漏色及颜色中的机械残影。A7V 旧调查坐标如炮塔 (3100,2800)、车体 (1800,400)/(2700,1600) 只用于该源图的诊断；后者涉及六轮共享纹素，不能当每车通用构件位置。见 [A7V 资源锚点](a7v-resource-contract.md)。

每个关键问题用同一检查ID关联Blender同机位近景、对象/材质/UV岛与PS原尺寸裁区。先定位再修改，改后明确重载纹理，复查共享/镜像UV的其他使用者；不能只看整车图猜UV位置，也不能只看平面图判断上车效果。先检查最终 DDS 头／语义／完整 mip，再从交付 DDS 读回原尺寸 RGB 在 PS 重查，并载回同一Blender模型核对位置和接缝；预编码 PNG 合格不能代替这一步。保存 CMPS 后复制到 verification 再打开，检查图层显隐、文字及代表区域；不拿交付原件做重开／撤销实验。

## 文件和磁盘同步收尾

每次 MCP 调用使用唯一会话目录，解包／转换／编译输出进入本任务专用 TEMP 根并记录新建路径。原则上同时只开一份完整 UV 与一份辅助文档，实际按内存和提交额度安排；不要生成重复 8K 渲染和完整 base64 日志。

客户端超时范围 1–60 秒。保存／编辑超时后先检查真实文档和文件状态，不自动重放批次。保留当前与上一份可回退检查点；验证完成后才回收已明确可重建的副本／导出。必要 PNG、结果摘要、哈希和失败诊断留下；先核对活跃引用和已登记身份，已登记文件先注销再处理。

本任务临时增量到 8 GiB 提醒收尾，到 16 GiB 停止继续生成大副本；C 盘空闲少于 60 GiB 时先安全保存和清理。这是任务阈值，不修改并不存在的编辑器缓存配置。保护其他任务文档及 recovery；不清空全局 TEMP、整个 recovery 或其他软件缓存。旧残留仅处理明确完成、无引用且有保留副本的项目。收尾记录清理清单、保留原因、逻辑回收量和实际磁盘变化，不把并发磁盘变化归因于本任务。

本包索引此前真实 MCP 的 [9 个原作原尺寸裁区](a7v-ps-study.json)（原捕获留在研究源） 及 [图板工程保存／副本重开记录](editor-evidence.json)。它们证明相应研究与显示检查，不证明未来制作或游戏效果已经合格。
