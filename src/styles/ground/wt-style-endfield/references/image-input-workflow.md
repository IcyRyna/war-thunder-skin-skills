# 图片输入与体积预算

本包的 **18 MB** 按十进制 **18,000,000 字节**控制。它是本任务要求，不是服务器官方上限。Skill ZIP、单批待传图像的估算编码量均应低于此值；常规图像批次优先在 1–3 MB 内。工具只能检查所给文件，不能测量或消除聊天历史中的既有图像与网络重试。

1. 原图、模型、原生 UV、Alpha、数据通道和工程保持原精度。轻量预览另存会话 TEMP 或当前任务预览目录，不能覆盖原始资料。
2. 先用长边约 1280–1600、JPEG 质量约 80–85 的整体图判断布局；字形、透明度、接缝看必要的无损 1:1 局部。精确颜色、Alpha、N／AO 用原数据检查，JPEG 不取代这些证据。
3. 给图记录来源 ID、原文件哈希／尺寸、裁剪坐标、预览编码／字节和观察目的。先用联系表筛选，再读选中图；不要每次改一个角落就重传所有旧图与整张 UV。
4. `python -B scripts/asset_pack.py budget <本批图文件...>` 估算 Base64 加固定预留；超限先拆批或压缩预览。保留必要细节，不为了凑预算降低最终生产精度。
5. 同一来源、版本、视角、裁剪和编码的图复用已有结论。有改模型、纹理、材料、相机或光照时先核对身份，再决定是否重看。用户要求复核时正常复核。
6. 记录本批已看／未看、结论、疑点、下一批需要的局部。文件存在不等于执行者已看，缩略图无缺陷也不证明原图通过。

不随 Skill 分发整套七视图、原始大 DDS／UV、模型、网页排版图板、失败构建和完整研究日志。必要参考按用途压缩并注明“观察用”。透明生产素材保留 RGBA／SVG，不转 JPEG。源参考大包留其原任务或已核验远端，不因体积预算重复下载。

及时永久清理本任务已确认废弃的下载试探、失败构建和测试副本；Windows 先读回核对绝对路径、归属、目录边界与重解析点，再用固定 LiteralPath 清单删除并确认不存在。现用输入、唯一源、模型、交付及其他任务文件不混入。唯一工程副本先完整备份并哈希核验。
