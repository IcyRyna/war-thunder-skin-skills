# Blender 模型与 PS 原尺寸 UV 双向对照

模型确认“在车上哪里、朝向如何、跨哪些构件”；PS／Composa 确认“对应纹素具体长什么样”。实际定位、绘制和验收都使用这两类证据。先在模型定位，再核对UV，修改后回模型；发现新问题再回UV，直到同一处问题两边都能解释。

## 开始前：两边必须是同一套资源

- 记录实际车型、子型号、附件状态，以及本次模型与颜色／N／AO输入的身份。在 Blender 中保留源模型的几何、材质分配和原生 UV；预览不要求重新建车、改拓扑或重新展开 UV。
- 确认模型的实际 UV 层和材质槽使用哪张图。PS 打开对应图集的原尺寸工作副本，保留结构、设计和诊断的分层关系。仅靠贴图文件名、车型方向图或图集外形，不能确认某个岛就是目标构件。
- 查询可用 Blender 连接／工具和 PS 类 MCP 的实时能力，保护已有场景、文档及未保存修改。Blender 工具须能核对真实模型、材质绑定和所用 UV；只得到一张整车渲染图，还不足以证明选对了 UV 岛。

## 1. 在 Blender 中确认位置与承载面

用整车视角确定问题所在，再给该部位近景；必要时换侧面、顶部、背面或隔离目标对象。检查其朝向、倒角、板缝、邻接件、遮挡，以及炮塔／车体等会独立运动的关系。可以隔离、选面和加临时诊断，但不要改动交付模型。

从目标对象或面核对材质槽、实际 UV 层和对应 UV 岛；可使用 Blender UV 编辑器的选面联动、真实 UV 线框或已核实的面到图集对应。记录该局部使用的纹理和范围，并核对镜像、共享、旋转、V轴翻转及可能的多图块。若对应仍不清楚，可在诊断副本上加独立颜色／编号，载回模型核实后撤除；未解决前不猜位置上色。

## 2. 回到 PS／Composa 看原尺寸纹素

在同一张纹理上定位已经确认的区域。每个关键局部做 1:1 检查，裁区原则上不超过 2048×2048；整图缩略图仅用于整体分区。UV线框和定位标注独立成层，不烘入最终贴图。

重点检查文字是否缺笔或被切断、徽记是否完整、黄线及负形的边缘、倒角和板缝的接续、孔壁漏色、相邻岛污染、机械残影，以及 C、N、AO 中各自的结构。C 全零 Alpha 仍可能有有效 RGB；用正确 RGB 查看副本检查颜色，原 Alpha 和打包数据按各自语义保留。

Blender 与图像坐标的原点可能不同。记录像素框、方向和图集尺寸，并用实际标记校准；不要对所有图集统一猜一个翻转。共享／镜像 UV 会影响多个构件，修改前列出其他使用者，并逐一回模型查看。

## 3. 修改、载回、再检查

在可编辑工程中修改对应图层，导出新检查副本，再明确重载到同一个 Blender 材质绑定。确认没有使用旧图像缓存或错绑同名文件。颜色与N/AO的色彩空间、通道解码沿用本车已核实契约，不把打包 N 直接当普通彩色法线。

保持同机位和尺度比较前后：UV 中看似顺直的线，贴到倾斜／曲面后可能变形；PS 中清楚的字，上车后可能被构件切开、遮住或变成反字。反过来，整车上看着正常的微小字、边缘糊化、邻岛漏色也要回 PS 复查。先解决本次改动区域及其共享使用者，再展开其他部位；不要求为每块无关部件生成成套截图。

## 4. 最终验收仍走两边

编码完成后，依据交付 BLK／资源绑定读回最终 DDS，核对文件哈希。把读回结果送入 PS 原尺寸检查，并载回 Blender 核对实际上车位置、变形和接缝。预编码 PNG、旧缓存、效果图或漂亮灯光不能代替这一步。

有些展示器会为性能缩小颜色、N或其他贴图；记录实际加载尺寸和转换方式。模型视图用于判断位置和空间关系，原尺寸细字与纹素质量仍由 PS 检查。Blender 材质近似和正常外观也不等于游戏效果已通过。已有缺陷若源模型、源材质或工具能力不能解释，保留范围说明，不用重铺整图掩盖。

## 成对记录与未完成项

每个重要改动／疑点使用同一个检查ID，将下面的信息关联起来；可写进本任务现有检查报告，不必另造一套目录：

| 模型侧 | UV／贴图侧 |
|---|---|
| 车型、模型身份、对象／构件、材质槽、UV层 | 图集／资源身份与哈希、原尺寸、像素裁区和方向 |
| 同机位近景、对象或选面的定位依据 | PS／Composa文档与图层、1:1局部、必要的UV线框 |
| 修改前后的位置、变形、接缝和遮挡 | 修改前后的字形、边缘、负形、通道与邻岛影响 |
| 共享／镜像UV的其他使用者复查 | 最终DDS读回身份、实际重载结果和剩余问题 |

原作解析时也用相同方法：先在范本模型确认真实构件，再看原作UV细节，区分“直接观察”“布局解释”和“尚未证实的对应”。做新车型时重新确认对应，不能把A7V坐标迁移成通用遮罩。

没有 Blender 或没有 PS 类 MCP 时，可以先完成可用的一侧并保留输入，但另一侧标为 `not_run`；对应不明标为 `unresolved`，不能把成对检查填成通过。包内 `tank_preview.py` 可辅助排错，但它是 ModernGL 近似预览，不能冒充一次 Blender 检查。这个方法规定核对依据，不规定黑白比例、徽记坐标或必选布局。
