# 模型确认位置，UV 核对细节

这是 0.1.1 的前置研究与制作方法。模型与 UV 各自回答不同问题，通过同一个材质资源与 UV 岛把答案连起来。

| 对照面 | 应确认的内容 | 单独使用的缺口 |
| --- | --- | --- |
| 原作实际模型 | 装在什么部位、朝向、板缝、前后/左右、邻接、遮挡、运动关系 | 远看可能认不清线条、字样和抠图残片 |
| 同一模型的原生 UV / 原图 | 图形长什么样、字向、线路连接、蜂窝格数、间隙、边缘和原生像素 | 单看平铺图容易误判实际部位、左右、旋转与比例 |
| 目标模型＋目标 UV | 对应承载面、图文可读性、共享/镜像、跨面与细节预算 | 只有这一步才能判断迁移是否适合目标结构 |

## 实际操作

**先确认源身份。** 从 BLK 的 from/to 和模型材质槽建立映射，不能靠文件名里的车型猜。当前原包虽然使用 sep3 名称的 C/N，实际模型为 m1a2_sep2_trophy。固定 ZIP、模型、C/N/AO 与附属资源哈希；只为研究原作时，可以将原作者的 N 加载到原车。目标车依旧使用本车材质来源。

**在模型选部件，再查 UV。** Blender 使用 UV Editing，两窗分别显示真实模型和图像/UV。按实际节点选中部件，确认活动材质；图像编辑器选择该槽对应的原始 C 图，再进入编辑模式核对 UV。部件有多个材质时逐槽查，不能把任意活动图片当成对应资源。需要时隐藏相邻遮挡件，记录隐藏状态。

**从 UV 反查模型。** 在图像里圈定图形边界，检查实际选中的面、共享副本和镜像对象。图片坐标以左上角为原点：x=u×W，y=(1-v)×H；不能把该换算当成载具所有导出器都已验证。超出 0–1 的重复 UV、背面、互斥附件和隐藏部件分别记录。UV 包围框可能碰到小螺钉等共享碎片，矩形相交不是“它们都属于同一块板”的证明。

**看原像素。** 分别看原尺寸、局部放大与模型近景。检查文字是否原本可读、蜂窝数量与格缝、线路分支/端点、孔口与实际透明边缘。原作细节本来就小，模型或图像插值的模糊要与误搬整块表面区分。未知微字保留为不可读微纹理或明确省略；不得让模型补成新内容。

**再提取，再有限修复。** 先确定图形覆盖与保护区，分离纯元素、完整研究面板和背景。Alpha 存在不等于板底、源车螺钉、阴影和磨损已经清干净。生图只修明确缺损；回写范围及 RGB/Alpha 模式仍受局部修复接口约束。以模型＋UV 对照图核对修复有没有改字、删线、增格、留残片。

**迁移到目标车时再做一遍。** 按源部位用途和布局关系找目标承载面。目标没有相应部位时，记录适配理由、缩减或省略；不在任意装甲上硬塞同类图案。模型与 UV 都通过后，再冻结最终图形、实际尺寸与采样预算。最终 DDS/mip 读回并重新绑定目标模型；离线渲染不替代游戏检查。

## 必留的区域记录

每个区域至少有：精确源模型身份与哈希、原包身份、材质资源与绑定文件、原贴图哈希/尺寸、UV 范围、实际节点、模型图、UV 图、方向/共享结论，以及“源用途 → 目标部位”的理由。图片与记录采用文件 SHA-256 关联。

`scripts/source_model_uv.py --study SOURCE_STUDY.json` 检查已配对区域；`--plan PLAN.json` 同时检查放置项与目标对应说明。它检查证据身份与完整性，不能由布尔值证明语义正确，也不自动认可美术。0.1.1 的 compose_native 在输出前调用相同检查；自编生产脚本同样调用 validate_plan，不可仅在报告里写“已看模型”。

原车模型和整套游戏资源由制作任务提供，不随风格 Skill 重复分发。包内对照图是本次研究证据，不是新车坐标预设。
