# 作品与文件命名

新作品先确定真实车型、短主题名与稳定work_id，记录必要的公开名称、游戏目录和内部版本对应关系，不要求中央登记。已有作品沿用当前实际身份；修订涂装默认同步既有实际选择目录，不为了采用新规范自动改名旧作品或造成多个同名近似涂装。

| 对象 | 规范 | 新作品示例 |
|---|---|---|
| 公开标题 | 车型全称「短主题名」· S42 | 勒克莱尔 AZUR「玄墨」· S42 |
| 本地游戏ZIP | 车型_主题_游戏涂装.zip | 勒克莱尔AZUR_玄墨_游戏涂装.zip |
| 新游戏文件夹 | 稳定ASCII车型_主题_S42，无制作号 | Leclerc_AZUR_Xuanmo_S42 |
| 稳定作品ID | 小写ASCII与连字符，建立后复用 | leclerc-azur-xuanmo-s42 |
| GitHub附件名 | ASCII文件名，中文写label | leclerc-azur-xuanmo-s42-skin.zip |
| 展示图 | 稳定作品名或preview/hero等角色，无制作号 | preview.png / hero-front.png |

玄墨仅为命名示例，不表示已有该作品或已获发布认可。主题名应短、与实际画面对应；避免“最终版、最新版、修正版、测试版、vN/rN”等制作序号进入公开包名、游戏文件夹和展示图。车型固有数字与变体字母必须保留，如99A、2A6HEL、2A7V，不把它们误当修订号删除。

真实制作版本保留在任务、包校验、源工程和发布登记中；源码内部已有目录/修订名按原工程保留，不能为了统一公开名称破坏引用。作品版本与Skill的0.1.5编号是两条身份，不混用。

游戏BLK和资源from/to名依真实车型和绑定契约，不能随公开标题机械重命名。旧游戏目录改名需要明确迁移范围，先更新实际选择名、安装路径、配置和回执，再核对；不擅自碰用户别的涂装目录。

在沿用本工作区GitHub约定时，历史版本标签使用登记的works/<work_id>/v<实际版本>，当前入口用已授权的current标签；公开简介只在必要时使用不体现顺序的短标识。标签中的真实历史身份不要求改写成公开文件名。新上传先核对当前仓库身份与暂停发布对象，不能重放旧脚本恢复其他作品。

当前游戏ZIP只装运行所需配置与纹理，不混入宣传图、CREDITS.txt或SHA256SUMS.txt；简介在GitHub作品页/Release，展示按需另交。默认不再交付或保留源码工程ZIP，体积与收尾按[包体预算](package-budget.md)执行。用户本次明确要求其他附属形式时按该范围处理，不据此改写所有旧包。
