# 现有工程副本：真实回放与美术复核

用户要求用本Skill检查旧工程时，复制实际现用工程和模型，冻结本次用到的输入哈希。复用其已确认设计选择；本车旧的提亮、无字或布局决定不会自动成为其他车型默认。无需恢复整个旧工程目录或建立中央登记。

## 回放做到哪里，就报告到哪里

1. 在真实编辑器打开副本，核对层树；隔离导出底色与实际装饰层后恢复原状态，保存，复制保存结果并重开、导出。记录每份工程的实际调用和像素比较。
2. 从实际导出重新生成canonical与DDS，明确C网格变化和N/AO独立通道处理，逐mip核验并回读游戏ZIP。runtime的state=preserve若基线是已有涂装，只表示相对该涂装不变，不能说原厂原皮未变。
3. 在本车原生模型副本上重新绑定全部最终DDS，检查几何/UV不变，所有使用的原生及新增图片均可加载（外部文件或有效内嵌数据）。旧相对路径缺失但有有效packed image时不误报丢图；缓存看起来正常也不能代替保存副本重读。
4. 按AZUR的构成职责检查主要区域与小件，使用必要局部和转光；不是只看工具退出0。图组的核心文字单独验遮挡，被附件挡住时重排/换承载面，不能靠斜条露出或整图有颜色宣布文字可读。
5. 对原皮保留做同UV局部见证；按真实面组检查材质。生成当前问题单并修正Skill中导致遗漏的规则。若用户还要求修好作品，再在副本完成相应改图及受影响导出复验。

已有层的隔离/恢复是有效回放，不是新增设计。完整工具回放、运行文件通过、严格manifest完整和美术完成是不同结论；报告必须分别说明。旧工程缺少完整面组或合格素材/布局对应时，保留严格入口拒绝，并继续可独立完成的实际编辑器、DDS、场景和原皮诊断，不把诊断停在第一个缺字段。

回放中发现的问题按[常见症状与诊断](troubleshooting.md)定位，修正后同步更新Skill中导致遗漏的规则。
