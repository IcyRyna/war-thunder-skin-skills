# 获准上传GitHub时，涂装简介必须同步完成

制作阶段先准备完整、可审查的作品简介、文件命名映射和Release文案。实际上传在本次具体发布授权范围内执行，已有明确授权不重复询问。要求写简介不自动授权上传未审作品、更新正式Skill或恢复暂停发布对象。

## 简介必须回答的内容

1. **这是谁的涂装、给哪辆车。** 准确车型/变体、公开作品名、适用客户端和已验证的安装路线。不要把需要WTG原生模型组件的改UV包写成普通UserSkins即可通用。
2. **这套设计的特色。** 用具体部位写灰阶几何、蜂窝主带、顶部/首上、车型贴纸、车尾橙黑线和材质分工。只描述实际存在的效果，不写空泛“高级PBR/完全真实”，不宣称并未制作的浮雕或功能。
3. **怎么安装和更新。** 使用实际游戏文件夹名与相对安装路径，说明刷新/重选；有额外模型组件时另列。不得公开本机绝对路径或让用户在几个相似测试目录中猜。
4. **下载分别是什么。** 仅列实际保留和获准上传的游戏、展示/研究附件，默认不制作、不保留、不列涂装源码ZIP下载；链接指向真实上传附件；本地中文名与GitHub ASCII名/中文label对应。
5. **完成与验证到哪。** 已认可、部分认可、待评价或需修订按实际登记；技术核验、离线预览、游戏反馈分别说明。发布授权不等于全部细节认可，尚待确认的镜片/材质等不隐去。
6. **来源和使用范围。** 参考作者/作品、素材来源与许可按实际证据注明；自行代码MIT不自动让所有纹理/参考图片都变成MIT。保留应有归属，不把改写图形说成原作者原像素。

默认用清楚中文介绍，需要面向英文读者时附简洁英文，两个版本的事实和状态保持一致。不要把内部聊天、训练/评测长日志、机器环境、未审候选推理或用户私人交流塞进公开页面。

## 发布落点与检查

- 仓库作品README写完整简介，根作品表列准确标题和链接；Release附精简设计说明、实际状态、安装路线与文件SHA-256。参考模板在references/publication-templates。
- 普通README文本及用户选择的交互预览/既有图片互相配合。简介不可由“只有下载链接”替代；网页交互预览不自动授权七视图生成。
- 上传前替换模板全部字段，核对标题、车型、目录、附件名、来源、状态和授权边界。最终游戏包须通过[双体积门禁](package-budget.md)，记录ZIP与解压实际字节；不再要求源码ZIP附件或当前/完整回退工程对。
- 上传后逐个检查作品页链接、图片/交互资源及附件可访问性，回读附件SHA-256；只报告实际完成的上传。外部失败保留明确原因和本地可审查结果，不自动扩大到换库、改历史或恢复其他作品。

## 基于已知AZUR事实的简介写法示范

这套勒克莱尔AZUR专用S42涂装以深炭灰和相近灰阶几何分块构成主体，侧裙连续蜂窝、炮塔局部身份标识、稀疏青色刻度与橙黄黑警示形成工业科技层次。车体与炮塔保留细磨砂、焊缝和结构细节，并用适度金属光泽、深黑观瞄壳体及独立光学表面区分材质。车型文字与装甲面按本车重新排布，后部警示和顶面装饰呼应侧面主带。

发布这段示范时仍须加入实际下载、安装和当前验证状态。历史AZUR认可不能自动覆盖后续圆镜试验；其他车型也必须重写名称、部件和实际完成项。
