# 材质、Alpha 与诊断

当前 AZUR 的关系优先，车型参数留在案例。主体磨砂金属、较轻蜂窝反射、较深火控壳体和镜片分别设遮罩。黑色金属不表示黑金双色，也不要求画黄边。先看同一照明下高光宽度与层次，再决定本车数值。

| 症状 | 先查 | 不应直接归因 |
|---|---|---|
| 游戏偏绿／偏色、离线正常 | 实际纹理绑定、固定颜色覆盖、shader 和每级 mip 的 Alpha | 自动认为是缓存、钩子或“还不够黑” |
| 黑灰脏斑仍在 | C 的连续映射和真实漆面统计，再分别查 N.R/B、G/A、AO | 只看整张图中位数；暗像素全当孔洞 |
| 去污后失去磨砂 | 高频细纹、法线扰动、粗糙度与低频污渍的处理范围 | 用常数 N 或全局去噪把结构一起抹平 |
| 左右色差／旧贴纸重影 | 两边整片 C 的分位数与旧底板，之后查 N/AO 和同光照 | 擦掉旧橙条轮廓就认为整片底色也一致 |
| 天空蓝镜面 | 表面反射强度、粗糙度、环境与目标材质角色 | 仅通过改 RGB 解决所有反射问题 |
| 镜片灰白或没有反光 | 同图像素的 C.Alpha、玻璃 shader、镜片 N，逐区域对照原输入 | 认为外壳修正覆盖了镜片，或盲目全图 Alpha255 |

Alpha 至少有四种不同职责：图形贴花覆盖、固定漆面 C 覆盖、玻璃／裁切 C 透明数据、打包 N.A 法线数据。核实每个像素所属材质与共享者。已确认 dynamic_masked_tank 的不透明固定漆面可完整覆盖；未知、玻璃和 alpha-test 不能套用。**同张纹理可能同时被钢面和镜片使用，shader 白名单只是必要条件，不能代替像素保护区。**

修改前声明纹理、通道、允许区、保护区和基线哈希；修改后检查遮罩外精确不变、声明范围内的变化与所有 mip。DDS 读取库可能输出 BGRA；AZUR 本次内存视图的 B 是索引 0，不能照 RGBA 索引猜写。C／N 的物理含义仍按资源实证确认，不能只靠文件后缀。

AZUR v28 恢复镜片 C.Alpha 后用户确认方镜正常。v29 又在圆镜内侧试用 N.B147，保留其他声明通道；这是后续反射实验，尚待游戏反馈，不能写成恢复原值或跨车光学配方。A6HEL 的镜片工具仅改已确认玻璃 N.R；这与 AZUR 圆镜试验属于不同输入和故障，不互相替代。

清理银白误涂时 C 与相关抛光 N 要一起回退；保持 G/A 或缩放 G/A 的声明必须与实际一致。增加颜色不自动产生凹凸，单纯存在 N/AO 文件也不证明每个图案都新做过法线。
