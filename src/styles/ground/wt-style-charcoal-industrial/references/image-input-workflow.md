# 大量参考图与预览的输入流程

适用于涂装研究、原作／目标车对照、素材检查、模型预览及验收。目标是保留全部资料并减少无必要的重复传输，不限制合理的看图数量，也不降低生产和交付标准。

## 原图与预览的职责

1. 原始下载、用户参考、完整纹理、带 Alpha 素材、模型与可编辑工程继续保存在任务既有 `assets/`、`reference/`、`source/`、`editor/` 等目录。不得以减小请求为由覆盖、重编码、删掉或降采样原件。
2. 轻量预览、局部放大和联系表另存到本任务新的 `previews/vN/ai-review/`；索引与检查记录放 `reference/` 或 `verification/`，遵守所属项目的目录和登记规则。不在本地 Skill 的 `assets/` 中生成缓存或预览。
3. 预览只服务当前观察。最终交付图、游戏纹理、材质通道、无损基线、原尺寸 UV 检查及源工程的精度和格式要求沿用具体风格 Skill。

## 选择合适的视觉输入

| 目的 | 优先查看 | 精度例外 |
|---|---|---|
| 整车配色、主次、布局和视角筛选 | 保持比例的 JPEG 预览或带编号的联系表 | 需要辨认小部件时单独放大 |
| 铭牌、小字、图形边缘、UV 接缝 | 从原图取得当前区域的无损局部 | 像素关系检查保留 1:1，并标明裁剪坐标 |
| 精确颜色、Alpha、N/AO、数据通道 | 原始／无损数据及数值检查，必要时另做带说明的可视化 | JPEG、背景合成图不能作为这些项目的精确证据 |
| 最终视觉或游戏验证 | 规定分辨率的正式证据，整体与局部配对 | 联系表和轻量预览不替代规定验收 |

整体预览可从长边 1280–1600 像素、JPEG 质量 80–85 开始，以实际可读性、文件字节数和用途调整；这是工作起点，不是官方限制或强制压缩目标。细字看不清时提供局部，不把整个图集反复升到超大尺寸。涉及精确位置时记录原图尺寸、裁剪区域与缩放，坐标必须映射回原图。

原图含透明度时，预览可以在明确标注的背景上合成，但原 Alpha 必须保留。无损裁剪允许保留必要细节；不得用 JPEG 预览作颜色取样、透明度判定或最终贴图输入。

## 大量图片的查看和记录

- 为参考图建立稳定 ID，例如 `REF-023`，关联任务相对路径、原图 SHA-256、原图尺寸、用途和来源。预览记录自己的路径、SHA-256、字节数、尺寸、编码参数、源图 ID 和裁剪坐标；不要把 Base64 内容写进索引或交接。
- 索引可采用 `reference/image-index.json`，已有等价索引时扩充原索引，不再造平行登记。路径登记与文件保留继续遵守项目规则。
- 先用联系表定位相关编号，再看当前任务需要的整图／局部。联系表应标注源图 ID、视角和版本，只承担筛选与整体关系展示；不能因为缩略图中看不见缺陷就判定原图通过。
- 一轮可优先采用一张整体图加少量当前问题局部；确需同时比较更多图片时按用途增加或分批，不能为满足固定张数而漏看证据。分批完成后汇总已检查与未检查的编号、对应结论和需要跨批复核的关系。
- 已得出的视觉结论写入任务现有检查记录：来源 ID／版本／哈希、观察部位、结论、用户反馈、未解决项及下次需要查看的图片。观察与解释分开；技术合格不等于用户认可，未检查项明确保留。
- 相同来源版本、视角、裁剪、尺寸和编码的预览优先复用。图像哈希只能识别图像字节；场景、纹理、材质、相机或渲染设置有变化时，核对其生产输入后再决定是否可复用，不能因路径相同就沿用旧结论。
- 对已经核对且本轮无变化的内容先读记录，避免循环打开同一组大图。用户要求重新检查、证据有变化或结论存在疑问时正常复核，不能拿“减小输入”拒绝必要看图。

## 模型预览与传输故障

修改后优先查看当前版本的一张整体图与变化区域，保留模型和原生 UV 的双向对照。不要每次微调都把所有旧视角、旧版本和完整大图集重复读入；原始预览和正式证据仍在项目文件中保留。

文件保存在磁盘上不等于模型已经看过；看图工具仍可能将图片内嵌到输入。API 的 `detail`、文本 token 预算、普通对话压缩和 HTTP 回退也不保证消除已有图片字节。出现重复断流时记录实际传输、重试、请求字节数及上下文状态，不能仅凭 token 数归因，也不能把建议值当作服务器大小上限。

本流程不自动修改聊天数据库、rollout、旧图片历史、代理或传输协议，不自动重启、归档、打断、发消息或建立新对话。完整阶段结束时整理文件索引、当前工程、用户确认项、未解决问题和必要最新预览；需要换对话时由用户决定，分叉可能继承旧图片历史。既有图片负担不因新增规则自动消失。

## 在 Skill 候选中复用

本流程已内置于当前炭灰工业Skill，不要求再调用其他Skill。后续新建／修订可分发的涂装 Skill 候选时，把本流程复制到候选自己的 `references/image-input-workflow.md`，从其 `SKILL.md` 添加清晰的相对链接，并检查包内引用自包含。不得在分发包写入本机绝对路径，不为纳入规则覆盖当前任务候选、锁定镜像、正式 ZIP、版本或发布状态；同步范围遵守本轮明确授权。
