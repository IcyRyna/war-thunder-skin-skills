# 游戏包体积与任务收尾

用户于2026-10-27明确要求，本页替代旧资料中默认交付源码ZIP、保留自包含工程及完整回退工程包的规定。

## 两项硬限制

- 最终游戏ZIP必须 **小于100 MB，即 < 100,000,000字节**。
- ZIP中所有实际文件的解压字节总和必须 **小于200 MB，即 < 200,000,000字节**；恰好达到上限也不通过。包含必需的原生模型组件时计入同一总量。
- 两项同时满足；不能只检查ZIP，也不能通过拆包、多层压缩、另附必装下载或删除mip规避。报告记录实际字节、文件数及大文件。
- 游戏包只放运行必需文件。源码、CMPS/PSD/BLEND、原始模型、PNG中间图、各级mip检查图、测试日志、回退副本与展示图不得混入。

交付前执行：

```text
python -B scripts/package_budget.py 最终游戏涂装.zip
```

默认逐成员流式回读并验证大小与CRC，不展开工程；非零退出码即停止交付和上传。`--metadata-only`只用于盘点，不能代替交付验收。`ground_dds.py`已在事务提交前调用同一门禁；其他打包入口也必须执行它。不要为超限包开豁免或宣称已合格。

## 为什么纯色也可能很大

未压缩RGBA8 DDS按宽×高×4字节占空间，与颜色种类无关。完整二维mip通常另增约三分之一。4096²完整链约89.5 MB，8192×4096约179 MB。ZIP可以压缩平色重复字节，但解压后恢复原体积；细磨砂、噪声和多个副本还会降低ZIP压缩率。BC3以4×4块存16字节，相同尺寸约为RGBA8的四分之一；它有损，不能把格式更小当作材质正确的证明。

先按BLK与真实模型列出必需资源、共享关系、原生尺寸、通道语义及每张DDS字节预算，再开始最终导出。优先取消误打包的副本、保持未修改资源使用原生引用，合理复用已确认可共享的资源；不能仅凭文件名相似删掉真实覆盖或模型依赖。

颜色图优先使用目标游戏/着色器实际支持并已验证的块压缩格式；现有工具默认生成BC3候选，RGBA8仅作需要时的精确对照。N/AO等打包数据按本车通道语义选择格式并验证误差；不能把带独立数据的RGBA强行改成丢通道的BC1/BC5。未知格式先确认能力，不能只改DDS头。原始输入和编辑阶段保持精度，所有导出保留完整mip、Alpha职责及色彩空间；不要通过反复有损转码、全图刷Alpha或粗暴降清来凑额度。

仍超限时先重新分配各材质的格式和分辨率预算，保护文字、蜂窝、磨砂与镜片；确需调整分辨率则作为具体变更记录，并在真实UV、最终DDS、全部mip及目标模型检查清晰度和通道。压缩后的最终文件须重新回绑模型，游戏反馈尚未验证时如实记录。体积通过不代表美术或游戏已获认可。
