# Akamywek 飞机布局

0.2.0 正式发布，使用新的「研究证据 → 风格关系 → 载具语义映射 → 实做检查」工作流。它是独立的 `wt-style-akamywek` 版本线，保留旧 `war-thunder-style-akamywek` 1.14 历史。发布许可与具体新作品的美术验收分别记录；本版的已测范围和待验证部分见[验证记录](references/tool-validation.json)。

目标是让人物、线条、字标和飞机体量共同构图。F2A 的尖束只是一个分支；浅底、宽翼身、双脊与鸭翼不能套同一组像素坐标。先读[构图决策](references/composition.md)，再按机体读[机型分支](references/airframe-families.md)。本次深化得到的构形、分视面反查与反例见[第二轮实物研究](references/deep-study.md)。

可核对的来源与限制见[参考案例](references/source-cases.md)，规则身份和证据见 [rules.json](references/rules.json)。

制作完整布局前先读[整机线条与立绘语法](references/whole-layout-grammar.md)：按五套原作选择人物、主形、标题和上下表面的分工；其中包含第三轮原生映射、实际换图失败与修正、阵风到J10C的鸭翼局部迁移。局部实做结果不升级成完整创作或全面精通的结论。

## 开始制作

**先区分单发与双发布局，必须在摆立绘和画主线之前完成。两类分别建立构图骨架，禁止把F2A／F16的单发窄中轴模板等比拉宽后套到双发机上。**

- **单发＋常规尾翼：** F2A／F16的 `single-axis` 分支以一条主要机背轴组织主形与嵌套负形，两翼人物向外展开，机背和字标走廊负责分隔；后部围绕单一发动机体量收尾。
- **单发＋鸭翼：** J10C这类单发鸭式三角翼单列 `single-canard-delta` 分支。保留单一机背纵向导向，同时把前部鸭翼短节奏、翼根过渡与字标区、后部宽三角翼人物场共同设计；主线进入宽翼面后按肩部／翼缘重新展开。人物主视觉落在已验证的主翼连续区，先核对前鸭翼遮挡；鸭翼使用独立短形与小标识。不能沿用F2A／F16的后平尾人物分配，也不能套阵风双发的整机宽度与双侧走廊。
- **双发：** 先处理宽翼身、两侧肩部、双纵向体量或中央沟槽，再安排人物与主路径。Su27选宽融合翼身、大主像／副像及横向动作联系；F15选双脊分路、独立纵向通道与两侧收尾；阵风选白色中央场、黑色两侧长字通道。双发可以有中央尖形，整机布局仍须符合所选双发分支。
- **鸭翼的作用：** 在整机选分支时就处理它与主翼的前后关系和遮挡；鸭翼上的短图形再独立适配。已有J10C实做只验证局部红白构形；本次新增的单发鸭式整机规则仍是待完整作品验证的方法候选。

在制作brief中写明「发动机类别、常规尾翼／鸭式等气动布局、具体分支、主线路径、人物承载区、字标／留白通道」。按[布局分支表](references/airframe-families.md)确认后再进入下面的制作步骤；双发稿若只剩单发大V加左右人物，或单发鸭式稿仍照搬F2A／F16的主翼—后平尾分配，回到构图阶段重排。

确认目标机型与改型、用户给定人物、参考分支、必留部位和需要修改的范围。沿用用户已经认可的部分。新作先锁定三件事：

1. **实际承载面。** 用当前机型的原生模型、UV 和颜色资源辨认机背、左右翼、机身侧面、垂尾内外面、平尾、鸭翼及机腹。核对朝向、共享／镜像纹素、切缝与活动面；不要从「单发／双发」直接推断具体 UV 或机械结构。
2. **主视觉。** 查看人物原图，选择最重要的脸、头饰和动作链。将它们放在连续、可读的面上；双翼不要求相同姿态或相同像素面积。先分清上／下／内／外表面和各个人物实例，再摆人物和文字可读区，决定线条走哪里。
3. **线条的职责。** 先确定主色场、主线、伴线、短节奏标记与安静区，再画图元。机背长轴负责导向，翼面负责展开，侧面负责长度和识别，尾面负责远看识别。不要把每个面都填成同样密度。

新载具先建立 [profile](references/vehicle-profile.md)。Profile 是真实输入与映射合同，内置工程脚本不会自动把 profile 变成设计稿。尚无原生映射时可以完成构图探索，但不能交付假称已经适配的游戏包。

## 工具与素材决策

- **编辑器看UV：** 按[编辑器与Blender流程](references/editor-blender-workflow.md)从真实材质域输出同尺寸透明UV线框，在原生PS或实际可用的分层编辑器中与颜色图、人物、装饰分层查看。先探测实际后端；Composa不等于Adobe Photoshop，CMPS不等于PSD。导出颜色前隐藏检查层并核对RGBA。
- **Blender看模型：** 用`blender_uv_review.py`载入真实网格、原UV与当前颜色，提供profile确认的上／前轴，保存带UV编辑区的独立`.blend`，按需检查当前部位。不得用重新unwrap或替代模型“修正”原UV问题。
- **按位置制作素材：** 先按[素材流程](references/generated-assets.md)写出目标表面、脸／动作锚点、身体方向和文字留白。已有素材不适合时，按任务需要实际调用内置imagegen生成／编辑人物或配套有机装饰；保留已指定身份与主题。精确主线、尖束、字标用可编辑几何和真实字体制作。
- **落位与复核：** 生图输出独立RGBA素材，精确位置、原生UV遮罩和回烘由编辑器／几何工具完成。检查源图关键部位和最终叠层，再回Blender看分量、接缝和遮挡；不能把生成的平面示意当作已适配纹理。保存实际提示词、输入／输出和工具结果，未跑通的后端明确标为未验证。

## 布局与制作

- 读[线条布局](references/line-layout.md)，画主路径与独立起止点，再设计宽度变化、分叉和负形。区分连通主形的内部负形、独立伴形和有限长度的重复序列；先确认该组的构形，再决定描边、切割或复制。
- 读[立绘布局](references/portrait-layout.md)，用原始人物的关键部位和实际机体承载面决定裁切、旋转与大小。脸能认出不等于动作完整；也不要为了保留每根头发把整个角色缩成邮票。
- 鸭翼、双垂尾或高机背涉及遮挡时，按[机型分支](references/airframe-families.md)单独设计。鸭翼是独立活动面，不能把主翼延长过去，也不能用一张俯视图证明全状态连续。
- 用包内 `scripts/vector_paint.py` 或当前已授权编辑器在原生 UV 上制作独立层。保存人物实例、线条、字标与背景，使用真实字体和原始人物素材。参考成品贴图可用于测量，不能冒充干净人物素材或作者原图层。
- 工程命令与依赖见[工程操作](references/technical-workflow.md)和[工具索引](references/tool-index.md)。工具默认色、线宽或材料值不是本风格规则。原 UV、机械保护域与未修改材质通道保持原约定。

## 每次实际检查什么

1. **布局分支与层级：** 对照brief核对发动机类别、常规尾翼／鸭式及具体分支。双发是否误套单发窄中轴；单发鸭式是否处理前鸭翼—翼根—后三角翼的节奏与遮挡，是否误用后平尾人物区；人物、主线、字标是否互相压住。发现布局分支错误，先返工骨架，再继续细节。
2. **关键局部：** 原图脸／头饰／手势与最终图层、实际模型逐一对照。检查源裁切、UV 裁切、几何遮挡和高光吞边，分别记录原因。不能用同一个「遮挡正常」结论覆盖这四种问题。
3. **线条：** 在俯视、相关侧视和斜视核对宽窄、暗缝、尖端、独立终点及跨岛接续。先确定形状关系，后调像素级抗锯齿。未获授权时不生成七视图宣传图。
4. **拓扑：** 查看左右翼和内外尾面、需要的机腹与鸭翼姿态。共享 UV 可要求两面共用图形、改位或取消文字；不能假称靠绘制顺序就能得到两个独立结果。
5. **文件：** 把ZIP解到临时目录，实际扫描 BLK 引用并解码颜色，并确认报告覆盖预期的非零对象数；退出码0但扫描了零个包不算通过。作者参考包也可能有缺失引用；发现后保留原件并记录，不能把参考包的配置照搬成新模板。

需要量化关键部位损失时，使用 [layout_audit.py](scripts/layout_audit.py)：输入**源人物关键遮罩、源到输出的仿射变换、实际输出人物层和承载遮罩**。它会报告出画布、落到非承载区和实际 alpha 丢失；不做自动审美打分，不推断真实 3D 可见性。用法见[检查器](references/layout-audit.md)。

大量图片按[图片输入流程](references/image-input-workflow.md)建立稳定来源 ID，先看轻量整体，再查必要的无损局部。原图和纹理保持原精度；不要反复加载所有旧图。

## 收尾与能力边界

交付可编辑源与实际游戏包，绑定输入、输出和检查证据。分别写清技术检查、代理视觉检查、用户评价、游戏实测与迁移／独立重复。作者的游戏截图属于来源观察，不能算本次新涂装的游戏通过。

用户禁止子代理时由当前代理自行完成研究、制作和验证；未执行的独立评测明确记为未执行，不用自检冒充独立重复。

本版包含四套主样本和鸭翼专项的观察与有限实验。它没有把已研究作品重新标成未见留出，也不声称已证明任意新机型的自主创作稳定性。新增规则、公开上传、安装或正式版本更新按用户对具体成果的放行范围执行。

Python 使用 `-B`，缓存和一次性工作放任务临时目录，不写回 Skill。共享工程工具来自固定公共源码，专属适配器与局部修订另行记录，身份见[tool-provenance.json](tool-provenance.json)；外部模型、游戏、解码器、编辑器与作者插画不内置。
