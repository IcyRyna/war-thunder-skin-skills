# 源人物关键部位检查器

`python -X utf8 -B scripts/layout_audit.py path/to/plan.json --out new-report.json`

依赖 Python 3.11+（使用 `hashlib.file_digest`）、Pillow 和 NumPy。输出必须是新文件；退出码 0 表示本项通过，1 表示发现关键部位损失，2 表示输入无效。脚本不修改输入。

JSON 的 `schema_version` 为 1，`canvas` 为 `[宽, 高]`，单位都是输出图层像素。`instances` 中每项含：

- `id`：唯一实例名；左右翼、尾面实例分别记录。
- `source`：原 RGBA 人物，`critical`：与原图同尺寸的灰度关键遮罩。遮罩大于 0 的像素都是必留点，不从裁切后的图层反推。
- `actual_layer`：从最终构建得到的该实例 RGBA 图层，`carrier`：同输出画布尺寸的灰度承载遮罩。两者必须使用实际 UV／设计坐标，不能只提供大致方框。
- 每个上述文件字段都是 `{ "path": "相对plan目录的路径", "sha256": "实际64位哈希" }`。不接受外部绝对路径、越界路径或链接。
- `source_to_canvas` 为 `[a,b,c,d,e,f]`，表示 `u=a*x+b*y+c`、`v=d*x+e*y+f`；以源像素中心 `(x+.5,y+.5)` 映射并取 floor 采样目标像素。
- `alpha_min` 可指定 1–255，默认 128；应使用生产实例已经声明的关键部位不透明要求，不能为消除失败临时降低。
- 行列式为负表示镜像，须明确 `allow_mirror: true`。这个选项只确认决策，不会检查文字或徽章是否适合镜像。

检查分别报告源关键点落到画布外、落到 carrier 外、实际导出 alpha 不足。计数以**原图关键像素**为分母；失败类别可能重叠，不相加当作独立丢失人数／面积。全透明原图、空关键遮罩、奇异矩阵、错误尺寸和哈希不匹配直接报输入错误。

检查不能判断画面中的 RGB 是否还是同一个角色、关键遮罩是否漏画帽尖、非线性投射或 3D 遮挡。缩小后多个源点落在同一目标像素也可能通过，因此通过之后仍检查原图与成品细节、实际模型及正常观看尺度。适用于 2D 仿射实例的定量复核，不取代人物视觉验收。
