# 新机型上手：从模型到第一版基本布局

一架没做过的飞机，按这个顺序走。每一步都有“过了没有”的判断，没过就不往下走。数字来自 J-10C（2026-10，莱万汀 v4 基本布局，第一次在新机型上只按规则画），换机型时照方法重测，不照抄数字。

路径约定：`G` 是 `scene_preview.py prepare` 输出的 `geometry.npz`，`S` 是同目录的 `scene.json`，`T` 是涂装那张颜色贴图的名字片段（J-10C 是 `j_10c_c`）。Python 一律加 `-B`，输出写到任务目录。

## 0. 照着做：清单

1. **干净场景**：`scene_preview.py prepare`，`--selection` 只列飞行状态的节点（机身、尾部、座舱罩、操纵面、喷口、光学件），不要挂架、外挂、起落架、减速伞。
2. **已用纹素**：`replica_check.py used --texture T`。覆盖率接近 100% 一定有问题（第 1 节）。
3. **岛地图和坐标**：`airframe_setup.py map --template 原厂贴图`。先从表里定轴：哪边是机头、哪边是左翼。不要假设（第 2 节）。
4. **左右共用的岛**：在地图上找出左右共用纹素的小件。这些地方的图形只能左右对称，不放字（第 2 节）。
5. **每块平面件的 frame**：`airframe_setup.py frames`。看残差，判断哪些岛能当平面画；展开的机身单独建“站位 × 周长”坐标（第 3 节）。
6. **干净底色和机械件遮罩**：`airframe_setup.py clean`。阈值从原厂贴图的统计里取（第 4 节）。
7. **平面形**：从 `coords.npz` 按展向分段量前缘、后缘、翼尖、翼根，得出后掠角（第 5 节）。
8. **设计稿**：每块 UV 岛一个图表，`frame` 和 `island` 取自 frames.json，图形全部用米写（第 6 节）。
9. **试画循环**：`vector_paint.py` → 七视图 → `airframe_setup.py shares` → `design_lint.py` → Composa 1:1 → 游戏距离近景。一次只改一类问题（第 7 节）。
10. **交付后看游戏**：用户在游戏里看过才算数；按意见改的版本覆盖安装到同一个文件夹（第 9 节）。
11. 风格要求（部位职责、尺寸阶梯、面积比、验收）以所用风格的基本布局文件为准。

## 1. 已用纹素：先排除两种假覆盖

- **别的颜色贴图**：喷口、座舱常常有自己的颜色贴图（J-10C 的 `j_10c_nozzle` 用 `j_10c_n_rgb.png`），不在这张 atlas 上。场景里有不止一张颜色贴图时，`replica_check.py` 的 `used`、`plan`、`check`、`assemble` 和 `airframe_setup.py` 都要用 `--texture` 指名，工具不猜。
- **辅助件**：模型里可能藏着 UV 铺满整张图的小方块（J-10C `tail` 节点里一个 10 cm 方块，六个面都是 0–1 UV，纹素密度约为蒙皮的 150 倍）。`vector_paint.helper_triangles` 按纹素密度（超过同贴图面积加权中位数 8 倍）找出它们，已用纹素、接缝外扩和图表分配都排除它们。没排除时有两个后果：
  - 已用纹素变成 100%，接缝外扩完全失效，每条 UV 接缝都出暗边；
  - 每个图表的种子都落在它上面，第一个图表认领它；它的优先级最高，整张图每个纹素都按第一个图表重算，别的图表画的东西全被冲掉。
- J-10C 修正后已用纹素 70%。

## 2. 岛地图：每块 atlas 是机体哪里

```
airframe_setup.py map --geometry G --scene S --texture T --template 原厂贴图.tga --out WB/map
```

- `atlas-map.png`：按节点上色，标岛号、主节点和朝向。`islands.json`：每块岛的面积、3D 质心、平均法线、朝向。
- `coords.npz`：每个纹素的机体坐标 x、y、z 和法线，按 4096 尺度存。之后放任何图形前，都可以直接查“这个 atlas 位置是机体哪里”。
- `landmarks.png`：原厂图上叠站位线（每 0.5 m，整米白色）、中线（红）、顶/侧/底分界（黄）。
- **轴向从表里读**：用喷口和某一侧机翼的质心定。J-10C 是 +X 机头、+Y 上、+Z 右翼。第一次把左右写反，是因为没看质心就假设了。
- **网格贴图试渲染**：做一张每格写编号的网格图，替换颜色贴图，渲染俯视、仰视、侧视、斜视。一次就能看懂整张展开图（J-10C：左翼上表面在 atlas 上半，右翼上表面在下半，机身是中间一条横带）。
- **左右共用**：按左/中/右 × 朝上/朝下分组栅格化，每组腐蚀 2 px 后求交。J-10C 共用的只占已用纹素 5%：进气道内壁、机腹中线件、缝翼和机翼后缘的边条、减速板。

## 3. frame：判断在哪种坐标里画

```
airframe_setup.py frames --geometry G --scene S --texture T --out design/frames.json
```

- 每块 **UV 连通岛**一条记录（共享 UV 顶点的三角形算一块，和 vector_paint 的 `island` 规则一致）：主节点、朝向、种子、范围，以及最小二乘仿射 `atlas px = origin + x·a + y·b`。这个仿射直接就是 vector_paint 图表的 `frame`，单位是每米的 atlas 像素。
- 拟合先用和岛法线夹角 30° 以内的三角形，再迭代剔除离群三角形。这样同岛里弯曲的翼根过渡区不会把平面翼面的 frame 拉歪（J-10C 主翼上表面 99% 残差从 76 px 降到 13 px）。
- `residual_px.fitted` 是参与拟合部分的残差，`island` 是整块岛的残差。两者都小，整块可以当平面画；`fitted` 小、`island` 大，说明岛里有弯曲过渡，那一带只放大色场。
- J-10C 结果：主翼下表面 1.3 / 3.0 / 3.9 px（中位 / 95% / 99%），上表面 2.7 / 9.6 / 13，升降副翼、鸭翼 0.5–2.4，垂尾 3.4 / 8.0 / 10.6。
- **岛不等于节点**：缝翼和主翼、方向舵和垂尾是同一块 UV 岛；升降副翼每侧却是两块（内段 `elevon1`、外段 `elevon`）。按节点分图表，前一种会报 “seed is not on any candidate triangle”（前面的图表已经把这块认领了），后一种会让一段**完全不上色**。J-10C 第一版内段升降副翼漏画，渲染里看不出来，被误当成翼根楔形的一部分。逐个岛对设计检查“有没有图表”。
- **展开的机身**：残差很大是正常的，说明它不是一块平面。J-10C 的机身是一条横带：机背中线在 v ≈ 4120，u ≈ 2589 + 541·s（s 是站位，m），v 方向距离约等于沿蒙皮的周长距离（每米约 541 px，实测误差 2.5%）。这时图表 frame 写 `origin = [2589, 4120]`、`x = [541, 0]`、`y = [0, 541]`，设计坐标就是（站位，周长）。
- **展开坐标的有效范围要扫描**：同一条横带里，某些 v 区间属于别的岛，映射不同。用 `coords.npz` 逐站位检查“这一格的纹素是不是映射回这个站位”，再放图形。J-10C 主翼根位置高，机翼后方的机身侧面在展开图上只到周长约 1.0 m。

## 4. 干净底色和机械件遮罩

```
airframe_setup.py clean --geometry G --scene S --texture T --template 原厂贴图.tga --out WB/base [--skin-seed U V]
```

- 按岛判断，不按像素判断（否则星徽、编号的边会留下来）。原厂浅灰迷彩占 60% 以上的岛是蒙皮，整块刷底色；其余是机械件，保留原厂像素并写进 `mechanical-mask.png`（白色 = 保留），上色时传给 `vector_paint.py --protect`。
- 阈值先看 `islands.json` 里 `stock_stats_on_used` 的亮度和饱和度分布再定。J-10C 原厂蒙皮灰的中位亮度只有 128，第一次把下限设成 125，主翼被判成机械件。
- 原厂颜色不像蒙皮、但设计要盖住的岛（深灰雷达罩），用 `--skin-seed` 指定。
- 出图后在模型上逐个看剩下的浅灰小件（天线罩之类）：在蒙皮上就补 `--skin-seed`。

## 5. 平面形

- 从 `coords.npz` 取某一面（例如主翼上表面 `ny > 0.5`）的纹素，按展向每 0.25 m 一段，取 x 的最大值（前缘）和最小值（后缘）。
- J-10C：主翼前缘后掠约 53.5°（z = −1.10 处 x = 2.06，z = −4.35 处 x = −2.33），后缘 x ≈ −3.6，翼根 |z| ≈ 0.85，翼尖 |z| ≈ 4.68；鸭翼前缘约 51°，展向 0.67–2.22 m；垂尾前缘约 55°。
- 后掠面上的宽度按“垂直于前缘”给：水平宽 = 法向宽 / sin(前缘与水平线夹角)。J-10C 垂尾平行四边形按水平宽 0.16 m 画，法向只有 0.09 m，看起来像虚线；改成水平宽 0.30 m（法向约 0.17 m）才读成一列块。

## 6. 设计稿

- 写一个生成脚本（例如 `design/build_design.py`），输出 vector_paint 设计稿 JSON。设计源和生成脚本放任务 `design/`。
- 每块 UV 岛一个图表：`island` 用 frames.json 的种子，`frame` 用拟合的仿射，`u`/`v` 写这块岛所在平面的两根轴。左侧图形写一次，右侧按 z → −z 镜像；上下两面用同一组图形。这样上下自动一致、左右自动镜像，在 atlas 上又都是直线。
- 一个填充里只能写 `color` 或 `gradient` 其中之一。
- 马赛克方向：`angle` 0° 时三角形有一条边沿设计 x 轴。要让一条边沿 atlas 竖直方向：机身展开图表（设计 y = atlas 竖直）写 90°；主翼图表（设计 z 大致对应 atlas 竖直）写 80–100°。
- 字用 `images` 图层的 `text`，`text_pixels_per_metre` 设 1600 左右。每一侧从自己外侧读正：从这一侧看过去，屏幕右方和上方对应的设计轴，组成的坐标系是镜像的就 `flip`；上方对应负轴时再转 180°。J-10C：机身展开图表左侧 `flip`，右侧 `flip` 加 180°；垂尾左面 `flip`，右面不翻。推算后仍要渲染一次确认。
- 人物图片同理，先做一张写有“HEAD ↑”和“L / R”的标记图，以零旋转、不翻转放到每个图表上渲染一次，再定参数。J-10C：垂尾左面 `flip`、右面不翻；主翼两侧都是图片“上”朝 +z、“右”朝机头（沿对角线镜像），`flip` 加旋转 −90° 头朝机头；`flip` 加旋转 0° / 180° 让横图的长边顺弦向、上方朝机身。
- 一张图跨几块 UV 岛（主翼和两段升降副翼）时，每个岛的图表都放同一张图、同样的中心、宽度、角度和裁切，在机体上就是连续的一张。`design_lint.py` 把这种同参数跨图表的摆放算作一次，不报重复。
- 用 `replica_check.py plan` 写 atlas 像素计划时，原创设计的马赛克可以直接写 `{"cell_px", "angle_deg", "origin_px", "inset", "levels"}`，并用 `--provenance` 写明是独立构形，不要标成测量重建。

## 7. 试画循环

```
vector_paint.py --geometry G --design design/design.json --base WB/base/clean-base.png --protect WB/base/mechanical-mask.png --out WB/trial-N
scene_preview.py render ...（颜色贴图换成 trial-N/composite.png，七个视图）
airframe_setup.py shares --views WB/trial-N/views
design_lint.py --design design/design.json
```

- 收据里 `zero_hit_items` 必须为空。为空也要看每层的 `painted_texels`：某一层是 0、图元却都命中了，说明有别的图表在重画整张图（见第 1 节辅助件）。
- **面积比**：和风格文件的验收范围比。超出时改图形，不改阈值。J-10C 一路的改法：翼根深色楔形放大一档 → 签名色降约 1.5%；白色焦点加大 → 白色从 2.7% 到 5.5%；补上漏画的升降副翼 → 签名色升 2%，再把楔形放大一档。
- **design_lint**：`thin-white-line` 判“长于 1.5 m 且平均宽不到 6 cm 的白件”；`too-many-angles` 按 6° 聚类、镜像算两族。嵌套 V 要在角度族内排：每片的两条边各取一族，相邻两片共用一族，缝就等宽（J-10C 外层 [12°, 18°]、内层 [0°（贴背鳍条边）, 12°]）。
- **surface_map 的局限**：它按图表的世界轴判断遮挡和陡峭，对 frame 图表会把侧面的字和细线误报成“被盖住”。frame 图表只看它的接缝项，可见性靠渲染和 1:1 判断。
- **1:1**：在 Composa 里打开 8192 颜色图，`render` 的 `maxSide` 等于窗口宽就是 1:1，和参考作品同米制比例的窗口并排看。J-10C 在 1:1 下才看出三件事：背鳍条侧壁上 1–2 cm 的白细线（白楔画到了凸条侧壁上，通道半宽 0.11 → 0.135 m 后消失）；翼尖条纹在升降副翼接缝处错开约 10 px（主翼 frame 被翼根过渡区拉歪，改成只用平面部分拟合后对齐）；铰链缝的 1–2 px 暗线（铰链侧面占用的纹素，模型上就是铰链线，保留）。
- **游戏距离近景**：1:1 只能看边缘干不干净，看不出图形在游戏里读成什么。用 `scene_preview.py render --camera` 的近景相机，按约 100 px/m 渲染机背、垂尾，例如 `{"eye": [-0.45, 1.0, 0.18], "up": [1, 0, 0], "zoom": 2.6, "target_world": [1.3, 0.9, 0.0], "width": 760, "height": 900}`（J-10C 机背）。这个距离下 1 cm 只剩 1 像素：J-10C v4 的 1 cm 平行回声线、0.9 cm 描边，在游戏里读成梳子和虚线，审查指出相关处理需要修订。白色件至少 8 cm，切缝至少 7 cm，描边至少 1.2–1.5 cm（`design_lint.py` 的 `thin-white-line`、`thin-outline`）。

## 8. 窄而圆的机背

- 有凸起背鳍条的机型（J-10C 约 0.13 m 宽），凸条连同两侧侧壁做深色通道，白色焦点拆成左右两半，尖点顶到通道边。
- 背鳍条两侧真正朝上的只有约 0.25 m 宽，白片一往外就落到侧斜面上，俯视被压扁。缺口用 18° 族开宽，白色才有地方放。
- **白色焦点用构造线切格写**（`arrangement.py` 的 `region` + `cuts`）：先把缺口铺成一整块白色箭头（离缺口边 7 cm），再用等宽深色切缝切开，所有白块和切缝共用同一组线。J-10C v5 只切 3 道：两道 9 cm 的 12° V 形切缝，一道 7 cm 的水平台阶切缝。不要手写一片片尖片，也不要切太多道：v4 的手写尖片加平行回声线读成白板加梳子；4–5 道 6.5 cm 切缝读成鱼骨。
- 回声和描边落在两侧弯曲面上时会被压成断续细线，窄机背上不画回声。
- 镜像时让两半各自只用本半边的线（`"halves": "separate"`，`region` + `cuts` 自动设置）。否则另一半的镜像线会把本半边的格子多切一刀，一个种子只填到一小块，白色就漏了。
- 缺口变宽后两肩红色变短，肩部大字挪到缺口前方、座舱旁的红色上。

## 9. 安装和用户评价

- 交付后按用户要求装进游戏的 `UserSkins/`，每个任务只用一个固定文件夹，更新时覆盖，不再新建 `_vN` 文件夹。复制后逐字节核对，写安装记录。
- 不启动游戏，除非用户明确要求。用户在游戏里的意见优先于离线检查：J-10C v4 的离线检查（lint、面积比、1:1）全部通过，游戏里仍然被指出白色太弱，所以才有第 7 节的“游戏距离近景”。
