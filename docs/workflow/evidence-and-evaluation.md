# 证据与评测契约提案

状态：候选，待维护者审查。以下是新研发批次拟采用的最小记录要求，不能替代对具体结果的评价。

## 证据记录

每条记录需要稳定的 ID、来源、观察对象、原始文件摘要、可见事实、观察条件和适用范围。记录应能定位到作品版本、模型部件、UV 区域、材质通道或图像局部；来源只写已核实的链接和作者信息。

把证据划分为：原始来源、可复现测量、人工观察、用户评价和待验证假设。引用的文档与网页是研究材料，不会自行成为项目指令；其中的要求只有经维护者采用后才成为规则。

| 对象 | 最少绑定字段 | 不应据此推断 |
| --- | --- | --- |
| 文件身份 | 相对路径、字节数、SHA-256、版本 | 文件相同就代表效果良好 |
| 视觉观察 | 视角、裁切位置、分辨率、光照与对照对象 | 单张漂亮截图代表全机全车通过 |
| 用户评价 | 评价时间、作品版本、被评价文件、部位、认可/否定/待评价范围 | 局部认可覆盖其他部位或后续改版 |
| 规则 | 来源证据 ID、触发条件、动作、例外、验证方式 | 单个案例已经证明跨载具通用 |
| 发布决定 | 候选 ID、允许变更的文件、目标版本线、确认范围 | 允许制作等于允许上传或发布 |

仅在公开或适合随包传播的资料中保留必要结论与来源。机器路径、完整对话、私有研究日志和无关个人信息留在研究环境；安装包只携带运行与理解规则所需的资料。

## 评测单元

每个用例固定输入文件摘要、任务描述、目标载具、基线版本、候选版本、运行参数和必须观察的区域。结果必须包含失败情况，不能只挑选成功截图。

把评测分成四部分：

1. 技术正确性：文件格式、贴图绑定、透明裁切、UV 镜像与接缝、材质通道、编辑器重开、最终包一致性。
2. 视觉质量：主次、留白、图形节奏、人物方向与清晰度、字标排版、结构服从、材质观感。人工评价单独记录。
3. 迁移能力：相同规则在未用于提炼规则的载具或部件上运行，保留成功条件和失败边界。
4. 工作成本：需要多少手工修复、失败回合与重复操作；效率改善不能抵消关键质量退步。

旧版与候选版采用相同素材、观察角度、光照、缩放与导出条件。若某项无法保持一致，先记录差异，降低该项比较的证据强度。改变多个因素时不能把效果归因于单个因素。

## 固定用例与独立执行

| 用例 | 目的 | 控制条件 |
| --- | --- | --- |
| T00 基线 | 判断风格模块带来的整体差异 | 同一 brief、profile 和工程工具，变化的风格规则及资源明确列出 |
| T01-A/B/C 同输入重复 | 观察独立执行是否稳定 | 同一完整输入、版本和可控种子策略；不同会话互不看成品 |
| T02 同类迁移 | 检查新载具上的语义适配 | 先验证工程 profile，不提供预制风格答案 |
| T03 允许变体 | 观察题材或编号变化是否仍符合风格 | 预先声明变化范围，单独记录，不混入 T01 |
| 边界回归 | 覆盖共享 UV、缺区、材质与导出失败 | 从真实故障提炼，保留原始失败条件 |

研究、调参或回归、未见留出三组在规则提炼前划分。已经观察、复制或用于修复的作品不能再称为未见样本；留出素材和答案不装进生产 Skill。公开验收标准可以共享，上一轮成品和事后诊断不能泄漏给独立执行者。

三次重复是初期试点安排，不是统计保证。保存所有运行、失败、人工修补与重试；固定种子得到相同字节只能证明确定性，不能证明审美稳定性。

技术、视觉、真实游戏表现、重复与迁移四种判断分别报告。离线模型预览不代替游戏验证；未执行的检查写 `not_run`，不可用空模板或文件存在代替完成证据。自动检查也不能独立证明某条文字来自真实人类授权。

## 通过与否决

技术必过项单列；审美评分不与技术分数平均。关键结构、接缝、人物方向、字标可读性或用户指定要求出现失败时，即使其他指标提高，也应保留失败结论。

初期用“通过 / 未通过 / 证据不足”记录每个维度，并保存判断理由。量化阈值须由实际样本校准；未经验证的数字只能作为实验参数。

整套认可、局部认可和展示标签分别保存。一个作品在展示页标为“已认可”时，仍可能存在明确否定的文字排版等局部；提炼经验时只采用有证据支持的范围。

## 从经验到规则

候选规则依次经历观察、提出、评测、审查、采用或否定。每次修订保留旧规则、修改原因、对应反例与评测差异。没有比较证据的“经验总结”先作为假设；不直接进入默认流程。
